## 겹침 설계

- 포켓몬끼리 겹칠 수 있다. 시작할 때도 강제로 자리를 벌리지 않는다.
- 먼저 소환한 포켓몬을 먼저 그린다. 나중에 소환한 포켓몬이 앞에 보인다.
- 목록 갱신, 모습 교체, 드래그는 기존 소환 순서를 바꾸지 않는다.
- 숨긴 뒤 다시 소환한 포켓몬은 마지막에 그린다.
- 앱을 다시 시작하면 저장된 파티 순서로 소환한다.
- 클릭은 앞에 보이는 포켓몬부터 판정한다. 투명한 부분은 뒤의 그림을 판정한다.
- 화면 경계와 돌봄 이동은 유지한다. 성격에 따른 산책도 유지한다.

검사: 같은 위치에서 6마리를 소환한다. 반복 틱, 드래그, 재소환, 목록 갱신, 그림 교체를 확인한다.
렌더러 검사에서는 겹친 픽셀 색과 클릭 대상을 확인한다.

## S4 범위

기록상 다음 단계는 도감 해금, 상점, 진화, 모습 선택이다.
사용자가 겹침 수정과 S4 진행을 선택했다.
S5 설정창과 S6 배포는 별도 단계다.

### S4 계약

- `advance(save, now)`는 해금과 진화 없는 종의 단계 보상을 적용한다.
- `shop.buy`는 칸, 종, 민트, 먹이, 에버스톤, 색을 구매한다.
- 민트, 에버스톤, 색은 대상 마리에 바로 적용한다.
- 먹이는 공용 재고에 넣는다. 다음 밥에 하나를 사용한다. 밥 효과는 두 배다.
- 기본 밥은 계속 무료다. 기존 밥 대기 시간과 하루 친밀도 상한을 유지한다.
- `evolve`는 다음 진화만 허용한다. 갈림길에서는 종을 지정한다.
- `pet.look`은 같은 진화 사슬에서 해금한 모습만 허용한다.
- 색 구매 권리는 마리별로 보존한다. 일반색으로 바꿔도 다시 구매하지 않는다.
- 구매와 진화 전에 그림을 확인한다. 확인 뒤 현재 저장으로 조건을 다시 검사한다.
- 파일 저장을 완료한 뒤 무대 갱신과 알림을 실행한다.
- 새 종 구매와 진화에 실패하면 저장과 포인트를 변경하지 않는다.
- 해금은 진화 조건을 만족했다는 뜻이다. 종 변경은 사용자의 진화 명령으로 실행한다.

### 초기값

| 항목 | 포인트 |
|---|---|
| 두 번째부터 여섯 번째 칸 | 80 / 160 / 240 / 320 / 400 |
| 민트 / 먹이 / 에버스톤 / 색 | 40 / 10 / 30 / 200 |
| 진화 / 조건 해금 / 진화 없는 종의 단계 달성 | 50 / 10 / 30 |

단계 문턱은 친밀도 500과 1500이다. 같은 단계의 보상은 한 번만 지급한다.
스타터와 조건 없는 상점 종의 해금에는 포인트를 지급하지 않는다.
종 가격과 진화 문턱은 기존 `unlocks.json`을 우선한다.
새 값은 사용자 승인값이 아닌 구현 초기값이다. `data/shop.json`에서 조정한다.
