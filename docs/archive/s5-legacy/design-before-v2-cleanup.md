> **S5 재설계(2026-09-18):** 박스를 제거한다. 도감 등록·소환과 가방을 추가한다. 별명, 모습 선택, 먹이 판매, 에버스톤을 제거한다. 진화의돌은 별도 상품이다. 랜덤알은 작업하면서 부화한다. 진화 전 종도 등록을 유지한다. 등록되어 있으면 도감에서 다시 소환할 수 있다. [상세 설계](../../specs/s5.md), [명칭 사전](../../terms.md), [시안](s5-preview.html)을 따른다. 기능 구현은 아직 시작하지 않았다.

> **S4 구현(2026-09-18):** 겹침 허용, 소환 순서 표시, 해금, 상점, 진화, 모습·색 선택을 구현했다. [계획](../../work/s4/plan.md)과 [검수 기록](../../work/s4/review.md)을 우선한다. S5 설정창이 나오기 전까지는 메뉴와 CLI로 조작한다. S4 문서는 현재 구현 기록이다. S5 목표와 충돌하면 새 S5 설계를 우선한다.

> **S3 초기값 확정(2026-09-17):** 중립 기준으로 다음 값을 정했다. 켜 두기는 시간당 친밀도 +6이다. 토큰은 1천당 +1이다. 토큰을 지원하지 않는 작업은 시간당 +12다. 마리별 하루 친밀도 상한은 200이다. 포인트는 토큰 1만당 +1이고 하루 상한은 50이다. 배고픔은 시간당 +10이고 밥을 주면 −40이다. 활동성이 +1이면 걷기가 20% 늘어난다. 사용자 승인 후 구현했다. 세부 규칙·검증·남은 실기는 [S3 검토 기록](../../work/s3/review.md)을 따른다. 원본 Artifact의 예시 숫자보다 이 확정값을 우선한다.

터미널 창 위의 투명한 무대에 내 포켓몬들이 각자 성격대로 돌아다니고, 내가 개발하는 동안 친해지고, 배고프면 밥을 달라 하고, 친밀도가 차면 진화하며, 조건을 채우면 새 종이 해금된다.

## 화면 — 무대 (stage)

| 항목 | 설계 |
|---|---|
| 창 | 무대 창은 투명 BrowserWindow 하나다. 창 크기는 **따라가는 창 ∩ 그 창이 있는 디스플레이**다. 창은 `setBounds` 로만 옮긴다. 마리는 무대 창 안에서 움직인다. 옛 "창이 곧 펫" 방식의 이동 해석(자기 이동 구분, 드래그 유예)은 전부 사라졌다. 독립 실행은 맨 앞 터미널 창을 따르며 항상 위에 있다. 창 모드는 그 VS Code 창 바로 위에 있다. 이 판정은 1판 그대로다(`src/follow/`) |
| 그리기 | 캔버스 하나에 N마리를 그린다(`src/renderer/stage.ts`). 메인 프로세스가 40ms 마다 `StageFrame`(마리별 모습 · 배율 · 몸 좌상단 · 동작)을 보낸다. 렌더러는 마리별 `Animator` 로 프레임만 진행한다. 시트는 모습(look)마다 한 번만 보내 디코드해 둔다. 그림은 **PMD 전용**이다(2026-09-17 사용자 승인). GIF·시트 그림 로더와 `art` · `gif` · `pos` · `fps` · `scale` 옵션은 지웠다. 남은 CLI 옵션은 `dot` · `buddy` · `keep` · `click`다. 동반자 실행에서는 이 중 `buddy` · `click` 만 쓴다. 문서에는 CSP를 적용한다 — 스크립트는 자기 파일에서만 불러오고, 그림은 data URL로 넣는다 |
| 클릭 | 무대 창은 기본적으로 클릭을 통과시킨다. 메인 프로세스가 40ms 마다 커서 위치를 확인한다. 렌더러는 그 위치의 시트 알파값으로 **마리 id 또는 '없음'**을 답한다. 여러 마리가 겹치면 가장 위에 그린 마리를 답한다. 마리 id가 있으면 클릭 통과를 끈다. id가 없으면 클릭 통과를 켠다. 마리를 드래그로 들고 있는 동안은 클릭 통과를 끈다. 클릭 통과 설정(옛 이름 고스트 모드)이 켜져 있으면 항상 통과시킨다 |
| 드래그 | 드래그는 그 마리만 옮긴다. 놓은 자리는 마리의 `home` 값이 된다. `home` 은 **무대 오른쪽 아래를 기준으로 한 몸 좌상단 오프셋**이다(옛 앵커 오프셋과 같은 뜻). 동반자 실행과 창 모드는 `home` 을 저장 v2에 적는다. 세션 펫은 `config.json`에 적는다. 무대 크기가 바뀌면 마리는 오른쪽 아래에 붙어 따라온다 |
| 겹침 | 겹침을 허용한다. 먼저 소환한 마리를 먼저 그린다. 나중에 소환한 마리가 앞에 보인다. 드래그 · 목록 갱신 · 모습 변경은 순서를 바꾸지 않는다. 숨긴 마리를 다시 소환하면 마지막에 그린다. 재시작 때는 저장된 파티 순서로 소환한다 |
| 표시 | 마리마다 표시 · 숨기기를 설정창에서 토글한다. 파티에 있지만 숨긴 마리도 상태는 계속 바뀐다. 화면에 나오는 마리 수는 `min(칸 수, SAVE_RULES.slots.max)` 다 |
| 여러 창 | [스펙 미확정] 창 모드에서 창이 여럿이면 무대도 여럿이다. **임시 규칙(S2)**: 무대마다 파티 전원을 그린다. `home` 저장은 저장을 쥔(writer) 무대만 한다. 규칙이 확정되면 `src/main/party.ts` 한 곳만 바꾸면 된다 |
| 실측 (mac, 2026-09-17) | 2560×1324 크기 무대에 6마리를 띄웠다. CPU 사용률은 메인 1.1% + GPU 4.6% + 렌더러 4.8%로 합계 약 10.5%다. 목표선(10%)에 걸친다. 바뀐 프레임만 다시 그리는 최적화는 이미 적용했다. 다음 최적화 후보는 무대를 아래쪽 띠로 줄이는 것과 프레임 변화분만 보내는 것이다 |

## 성격 — 25개를 다섯 축으로, 축은 배율

이 앱에는 능력치가 없다. 원작에서는 성격 25개를 "어느 능력치를 올리고 어느 것을 내리는가"로 정의한다. 이 앱은 그 정의에서 **25개 이름을 다섯 축에 나눠 넣는 규칙만** 빌린다. 그 결과 25개 성격이 저절로 서로 다른 값을 가진다. 앱 안에서 축의 값(+1 · 0 · −1)은 모두 **배율**로 작동한다. 아래 배율은 예시다. 실제 숫자는 규칙표(`natures.json`)에서 손본다.

| 축 | 원작에서 빌린 자리 | 오르면 (+1) | 내리면 (−1) |
|---|---|---|---|
| 활동성 | 스피드 | 더 자주 걷는다. 더 빨리 걷는다. 켜 두기 친밀도 ×1.2. 배고픔 ×1.2 | 오래 서 있다. 켜 두기 ×0.8. 배고픔 ×0.8 |
| 대담함 | 공격 | 커서를 쫓는다. 클릭에 크게 반응한다. 에이전트 실패에 기분 −2 | 커서를 피한다. 실패에 기분 −8 |
| 안정성 | 방어 | 기분 변동 ×0.7. 잠이 빨리 든다 | 기분 변동 ×1.3. 잠이 늦다 |
| 사교성 | 특수공격 | 다른 펫 옆으로 모인다. 함께 있으면 기분이 오른다. 놀아주기 친밀도 ×1.3 | 거리를 둔다. 혼자여도 기분이 안 떨어진다. 놀아주기 ×0.8 |
| 인내 | 특수방어 | 배고픔 ×0.8. 방치에 기분이 늦게 떨어진다. 밥 친밀도 ×0.8 | 배고픔 ×1.3. 밥 친밀도 ×1.3 |

| 오르는 축 \ 내리는 축 | 대담함 | 안정성 | 활동성 | 사교성 | 인내 |
|---|---|---|---|---|---|
| **대담함** | 노력 | 외로움 | 용감 | 고집 | 개구쟁이 |
| **안정성** | 대담 | 온순 | 무사태평 | 장난꾸러기 | 촐랑 |
| **활동성** | 겁쟁이 | 성급 | 성실 | 명랑 | 천진 |
| **사교성** | 조심 | 온화 | 냉정 | 수줍음 | 덜렁 |
| **인내** | 차분 | 얌전 | 건방 | 신중 | 변덕 |

대각선 다섯(노력 · 온순 · 성실 · 수줍음 · 변덕)은 축이 0인 중립 성격이다. 변덕에는 "가끔 아무 축이나 잠깐 튄다"는 설명을 붙인다. 값은 기본으로 오르는 축 +1, 내리는 축 −1, 나머지 축 0으로 두고 `data/natures.json` 에 적는다. 성격은 얻을 때 무작위로 붙는다. 상점의 **민트**로 바꿀 수 있다. 화면에는 성격 이름만 보인다(설정창 마리 카드).

## 상태 — 마리별

| 지표 | 범위 | 오르는 것 | 내리는 것 |
|---|---|---|---|
| 배고픔 | 0~100 (높으면 배고프다) | 시간 × 종의 `hungerRate` × (활동성 +, 인내 −) | 밥 −40 |
| 기분 | 0~100 | 밥 · 놀기 · 찌르기, 함께 있기(사교성), 에이전트 턴 완료 | 배고픔 70 초과, 방치, 에이전트 실패(대담함이 낮으면 더 큼), 혼자(사교성이 높으면) |
| 친밀도 | 누적, 감소 없음 | 1판의 모든 원천을 그대로 쓴다 — 켜 두기 · 밥 · 놀기 · 찌르기 · **토큰(또는 일한 시간)** · 턴 완료. 하루 상한은 마리마다 다르다 | — |
| 잠 | 잠들기까지 남은 시간 | 입력 없음 × (안정성 +) | 입력 · 클릭 · 에이전트 일 시작 |

- 시간 원천(켜 두기 · 일한 시간 · 턴 완료)은 **무대에 나온 마리 전원**이 받는다. 다만 **마리마다 받는 양이 다르다** — 종 프로필의 배율 × 성격 축의 배율로 정한다(사용자 결정 2026-09-17: "포켓몬마다 시간에 따른 친밀도가 다르니 그 시간마다 주면 된다"). 밥 · 놀기 · 찌르기는 그 마리에게만 준다
- **일한 양** 계산: 연결된 에이전트가 토큰을 읽을 수 있으면 토큰을 쓴다(예: 1천 토큰에 친밀도 +1, 1만 토큰에 포인트 +1, 하루 상한 있음). 토큰을 못 읽으면 `running` 시간을 쓴다(1판). 훅이 `Stop`(턴 끝) 시점에 사용량을 상태 기록에 `usage: { in, out }` 로 적는다. 상태 모듈이 tick 에서 그 증분을 읽는다. 무대에 나온 전원이 마리별 배율로 나눠 받는다
- 배고픔이 높으면 펫이 밥그릇 쪽을 보거나 우클릭 첫 줄이 "배고픔" 을 먼저 말한다. 배고픔 자체는 친밀도를 깎지 않는다
- 종 프로필(`species.defaults.json`) 필드: `affinityRate`(시간 원천 배율), `hungerRate`(체중이 높을수록 커짐, 기본 스피드가 높을수록 커짐), `sleepiness`(체중이 높을수록 커짐), `moodBase` · `moodSwing`, `likes`(함께 일하기 · 놀기 · 모임 중 무엇에 더 반응하는지, 타입에서 기본값을 정함). 뽑는 규칙과 값은 **Claude 가 맡는다**(사용자 결정). Claude 가 1089종의 기본값을 만든다. 스타터 29종은 손으로 다듬어 다섯 종만 표본으로 보인다. 자주 보는 종은 `species.overrides.json` 에 둔다

## 도감 · 해금 — `data/unlocks.json`

```json

  "eevee":    { "starter": true },
  "raichu":   { "evolve": { "from": "pikachu", "affinity": 500 } },
  "umbreon":  { "evolve": { "from": "eevee", "affinity": 500, "when": "night" } },
```

|---|---|---|

| `party` | 파티 마리 수 | 저장 |
| `work` | 에이전트와 함께 일한 누적 시간 | 통계 `totals.workMs` |
| `streak` | 연속 교감 일수 | 저장 |
| `bond` | 특정 종을 가진 마리의 친밀도 | 저장 |
| `time` · `event` | 시간대 · 날짜 | 시각 |

- 조건 종류마다 판정 함수를 하나씩 둔다: `check(cond, world) → boolean`. `world` 는 저장 + 누적 통계 + 시각으로 구성한다. 조건이 여럿이면 전부 만족해야 한다
- **해금 ≠ 획득.** 해금되면 상점(`shop` 가격이 있으면) 목록이나 무료 획득 목록에 나타난다. 진화 조건을 만족해도 종을 자동으로 바꾸지 않는다. `evolve` 명령으로 진화한다
- 현재 S4 진화는 `evo.json` 사슬과 사용자 분기 선택을 따른다. S5에서는 에버스톤을 제거한다. 진화 전후 종의 도감 등록은 유지한다. [스펙 미확정] 진화의돌 계약은 새로 정한다
- 누적 통계 `totals` 를 저장에 둔다 — `workMs · presenceMs · turns · days · fed · played`

## S5 설정창과 메뉴

[스펙 미확정] 탭은 `파티 / 도감 / 상점 / 가방 / 설정`으로 제안한다.
연결 설정은 설정 탭 내부에 둔다. 화면 명칭은 [명칭 사전](../../terms.md)을 따른다.
파티는 여섯 칸으로 표시한다. 빈 칸을 누르면 도감을 연다. 도감에 등록된 종을 소환하거나 교체한다.
눈 아이콘은 표시 · 숨기기만 바꾼다. 소환 해제는 칸을 비운다. 소환 해제해도 도감 등록과 육성 기록은 보존한다.
상세 화면에서 별명과 모습 선택을 제거한다. 성격 변경과 이로치 도구는 가방에서 사용한다.
상점 분류는 포켓몬, 랜덤알, 도구, 파티 칸이다. 구매할 때 사용할 포켓몬을 고르지 않는다.
먹이와 에버스톤은 제거한다. 무료 밥 주기는 유지한다. 진화의돌은 별도 상품이다.
랜덤알은 작업하면서 부화한다. 부화 결과는 도감에 등록한다.
진화 전 종도 등록을 유지한다. 등록되어 있으면 도감에서 다시 소환할 수 있다. [스펙 미확정] 종별 육성 · 재소환 · 진화 승계 · 보상 규칙은 아직 정하지 않았다.
도감은 전체 종을 다룬다. 지방 선택과 검색을 제공한다.
우클릭 메뉴에는 이름 · 상태, 밥 주기, 놀아주기, 설정, 종료를 둔다. 트레이 메뉴에는 설정과 종료를 둔다.
그 외 상세 계약과 아직 정하지 않은 규칙은 [S5 계획](../../specs/s5.md)을 따른다.

## S5 저장 전환

아래 저장 v2는 현재 구현이다. S5는 도감 등록, 재소환할 육성 기록, 파티 배치, 가방과 알을 다룬다. 별도 보관 개체 모델은 폐기한다.
[스펙 미확정] 저장 버전과 이식 정책은 아직 정하지 않았다. 이식 정책을 정할 때까지 기존 별명 · 모습 · 먹이 · 에버스톤 · 이로치 권리를 임의로 폐기하지 않는다.
[확인 필요] 원본 백업과 실패 복원 절차, 개체 ID · 육성 기록 · 잔액 보존을 검증해야 한다.
기존 S4 모습 · 아이템 설명과 v2 예시는 새 화면 요구사항으로 사용하지 않는다.

## TypeScript 전환

- `tsconfig.json` 은 메인 · CLI가 부르는 모듈 · 도구를 다룬다. `strict` 와 `noUncheckedIndexedAccess` 를 켠다. `module` 은 `nodenext` 로 설정해 CJS로 출력한다. `src/` 를 `dist/` 로 빌드한다. `src/renderer/**` 는 제외한다
- `tsconfig.renderer.json` 은 렌더러(브라우저 ESM)를 다룬다. `module` 은 `es2022`, `moduleResolution` 은 `bundler` 로 설정한다. DOM lib 을 쓴다. `verbatimModuleSyntax` 를 켠다. `src/renderer` 를 `dist/renderer` 로 빌드한다. 메인과 렌더러가 공유하는 계약은 선언 파일 `src/shared/stage.d.ts` 로 둔다. 두 tsconfig 가 이 파일을 함께 읽는다(`.ts` 파일이면 rootDir 밖이라 거부된다). HTML 파일은 `src/renderer/*.html` 에 두고 `../../dist/renderer/*.js` 를 부른다
- `package.json` 설정: `main` 은 `dist/main/app.js` 다. `build` 스크립트는 tsc를 두 번 돌린다. `check` 스크립트는 `tsc --noEmit` 을 두 번 돌린다. `prepare` 스크립트는 `build` 를 실행한다(그래서 git clone 뒤 `npm install` 이 빌드까지 끝낸다). `start` 스크립트는 build 뒤 electron 을 실행한다. 배포용 `files` 에는 `dist/` · `data/` · `src/renderer/*.html` · `assets/logo/out/` 를 넣는다. 번들러는 쓰지 않는다. 개발 의존성은 `typescript` 와 `@types/node` 뿐이다
- 옮긴 파일은 옛 자리에서 지운다. 두 벌을 남겨 두면 진단이 거짓말을 한다(1판 원칙). S2 에서는 단위 넷을 병렬로 옮기는 동안 옛 앱을 계속 돌게 두었다. 통합 확인이 끝난 뒤 한 번에 지웠다(`main.js` · `preload.js` · `buddy/` · `renderer/` · `lib/state` · `lib/follow` · `lib/line-helper`)

- [확인 필요] 따라가는 창 크기의 투명 창에서 클릭 통과와 GPU 부하를 확인해야 한다(mac · Windows). 창 모드에서 창 위 z-order 를 유지하는지도 확인해야 한다

- [스펙 미확정] 성격 축의 배율 숫자. 사용자가 생각한 배율이 있으면 그 값을 쓴다
