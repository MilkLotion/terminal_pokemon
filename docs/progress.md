## 다른 PC에서 재개

인계 기준일: 2026-09-21. 작업 브랜치는 `main`이다.

1. 작업 커밋을 받은 뒤 `git status --short`와 `git log -3 --oneline`으로 상태를 확인한다. 로컬 커밋은 다른 PC에 자동 전달되지 않는다.
2. [실행 흐름 검수와 재개 절차](work/runtime-e2e/record.md#다른-pc의-재개-절차)를 읽는다. 이번 수정과 검사 명령은 해당 기록에 있다.
3. [S5 기능 계약](specs/s5.md)과 [Figma 열린 항목](work/s5-design-system-v2/feedback.md)을 읽는다. 과거 검수 결과를 새 PC의 실행 결과로 사용하지 않는다.
4. 아래의 다음 행동부터 진행한다. 첫 산출물은 사용자 흐름별 성공·취소·실패 수용 조건이다.

현재 앱은 S4다. S5는 화면과 기능 계약을 정리한 단계다. Figma 작업 완료 여부와 앱 구현 완료 여부를 구분한다.

| 문서 운영 | 현재 기준과 작업 기록을 분리했다. 작성 검수를 작업 절차에 추가했다. | [구조 정리](work/docs-organization/record.md) |

과거 검사 결과와 이번 재검수 결과는 각 기록에서 구분한다. 현재 창·명령 사용 방법은 [설명서](guide.md)를 따른다.
마리별 크기는 저장한다. `pet.set size=3` 명령은 아직 구현하지 않았다.

## 다음 행동

1. S5의 사용자 흐름별 성공·취소·실패 결과를 정의한다. 기존 실행 흐름의 E2E 검사를 재사용한다.
2. S5 상품 후보의 채택 근거를 확인한다.
3. Figma의 열린 디자인 항목을 수정한다. 수정한 화면을 다시 검수한다.
4. 채택한 기능의 저장 이식 계약을 정한다.
5. 확정한 기능과 설정창을 구현한다.
6. 임시 HOME에서 새 흐름의 실패 복원과 중복 처리를 검사한다.

상품 이름부터 정한 뒤 기능을 추가하지 않는다. 미확인 후보를 구현 범위에 자동으로 포함하지 않는다.

## 남은 플랫폼 확인

- Windows 배율과 마우스 입력을 확인한다.
- 여섯 마리의 CPU·GPU 사용량을 측정한다.
- macOS와 다중 화면 동작을 확인한다.
- 여러 VS Code 창의 파티 배분을 정한다.
- Codex·Gemini 토큰 읽기를 확인한다.
- PMD 특수 폼 매핑을 확인한다.
- S6에서 패키징·게시·로그인 자동 시작을 확인한다.

이전 mac 세션의 설치 결과를 현재 Windows 상태로 사용하지 않는다. 완료 이력은 [월별 기록](history/README.md)을 따른다.
