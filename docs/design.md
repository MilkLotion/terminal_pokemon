# pokebuddy 현재 설계

갱신: 2026-09-21. 현재 구현은 S4다. S5는 제품·화면 설계 단계다.

이 문서는 채택한 결정을 기록한다. 구현 상태는 [진행 현황](progress.md)을 따른다. S5 기능 계약은 [설정창 계획](specs/s5.md)을 따른다.
정리 이전의 결정과 예시는 [설계 보관본](archive/s5-legacy/design-before-v2-cleanup.md)에 보존했다. 과거 시안의 값은 현재 구현 규칙을 덮어쓰지 않는다.

## 제품과 실행

| 항목 | 결정 | 근거 |
|---|---|---|
| 제품 구조 | 상주 Electron 앱과 얇은 VS Code 확장으로 구성한다. 앱이 런타임과 저장을 맡는다. | [기동](../src/main/app.ts), [설명서](guide.md) |
| 독립 실행 | `pokebuddy companion`을 사용한다. 첫 실행에서 스타터를 고른다. 이후에는 저장된 파티를 복원한다. | [설명서](guide.md) |
| 실행 모드 | `companion`, `window`, `session` 식별자를 유지한다. 세션 펫은 게임 저장과 분리한다. | [파티](../src/main/party.ts) |
| 표시 구조 | 투명 창 하나에 최대 여섯 마리를 그린다. 마리별 크기·성격·표시 상태를 유지한다. | [표시 창](../src/main/stage-window.ts), [무대](../src/main/stage.ts) |
| 정식 로고 | 원본은 `assets/logo/src/logo.svg`다. 산출물은 `assets/logo/out/`에 둔다. | [원본](../assets/logo/src/logo.svg), [검수](work/logo/review.md) |
| 구현 기술 | `src/`에 TypeScript를 작성한다. 메인과 렌더러를 `tsc`로 각각 빌드한다. | [패키지 설정](../package.json) |
| S5 설정창 | 바닐라 HTML·CSS와 컴파일한 TypeScript ESM을 사용한다. 기능 구현은 미시작이다. | [S5 계획](specs/s5.md) |
| 문구 | 사용자 문구는 언어 파일에서 관리한다. 한국어와 영어를 제공한다. S5 명칭은 명칭 사전을 따른다. | [언어 파일](../lib/i18n/ko.json), [명칭 사전](terms.md) |

## 화면 — 무대 (stage)

| 항목 | 결정 |
|---|---|
| 창과 프레임 | 따라가는 창과 디스플레이의 교집합을 표시 영역으로 사용한다. 메인은 40ms 간격으로 `StageFrame`을 보낸다. |
| 그림 | PMD 그림을 사용한다. 렌더러는 시트와 마리별 애니메이션을 관리한다. |
| 클릭 | 그림의 알파값으로 대상을 판정한다. 겹치면 가장 앞의 마리를 선택한다. 대상이 없으면 클릭을 통과시킨다. |
| 드래그 | 선택한 마리만 이동한다. `home`은 표시 영역 오른쪽 아래를 기준으로 한 오프셋이다. |
| 겹침 | 겹침을 허용한다. 나중에 소환한 마리를 앞에 그린다. 드래그와 모습 변경은 순서를 바꾸지 않는다. |
| 숨김 | 숨겨도 파티 배치와 육성을 유지한다. 다시 표시하면 마지막에 그린다. 재시작하면 저장된 파티 순서로 그린다. |
| 여러 창 | [스펙 미확정] 현재는 창마다 같은 파티를 표시한다. 창별 파티 배분은 별도 설계가 필요하다. |

구현과 검사 근거는 [무대](../src/main/stage.ts), [렌더러](../src/renderer/stage.ts), [S4 검수](work/s4/review.md)에 있다.

## 모듈 규칙

각 모듈은 자기 데이터를 소유한다. 커맨드 처리기가 여러 모듈을 연결한다. 렌더러는 저장 파일을 직접 쓰지 않는다.

| 경로 | 책임 |
|---|---|
| `src/main/` | 기동, 창, 파티, 메뉴, 명령 등록, 종료 |
| `src/renderer/` | 포켓몬 표시와 스타터 선택 화면 |
| `src/follow/`, `src/motion/` | 창 추적과 마리별 움직임 |
| `src/state/` | 친밀도, 배고픔, 기분, 돌봄, 적립 |
| `src/dex/`, `data/` | 성격, 종 프로필, 진화, 해금 규칙 |
| `src/shop/` | S4 구매와 거래 처리 |
| `src/save/` | 저장, 잠금, mailbox |
| `src/agents/`, `src/hooks/` | CLI 연결과 활동 기록 |
| `src/shared/` | 저장·명령·표시 계약 |
| `src/tools/` | 자체 검사와 화면 검사 도구 |

S5 설정창 파일은 아직 없다. 기존 `art/`, `lib/`, `cli/`는 런타임 참조가 남아 있으므로 유지한다. 남은 JavaScript의 이식은 별도 작업이다.

## 성격과 육성

원작 25개 성격을 사용한다. 성격은 다섯 축으로 움직임과 상태에 영향을 준다. 값과 명칭은 [성격 자료](../data/natures.json)를 따른다. 움직임 배율은 [params.ts](../src/motion/params.ts)를 따른다.
S3 육성과 적립은 구현되어 있다. S2 당시의 적립 중단 기록은 현재 규칙이 아니다.
친밀도는 감소하지 않는다. 배고픔과 기분은 변한다. 숨긴 파티 포켓몬도 육성을 유지한다.

| 현재 중립 규칙 | 값 |
|---|---|
| 켜 두기 | 시간당 친밀도 +6 |
| 토큰 적립 | 1,000토큰당 친밀도 +1 |
| 토큰 미지원 작업 | 시간당 친밀도 +12 |
| 하루 친밀도 상한 | 마리별 200 |
| 토큰 포인트 | 10,000토큰당 +1 |
| 하루 포인트 상한 | 50 |
| 배고픔 | 시간당 +10 |
| 밥 주기 | 배고픔 −40 |

정확한 계산과 돌봄 제한은 [상태 규칙](../src/state/rules.ts)을 따른다. 구현 검수는 [S3 검수](work/s3/review.md)에 있다. Figma의 친밀도 100 예시는 런타임 상한 변경의 근거가 아니다.

## 도감 · 해금

현재 S4는 [해금 자료](../data/unlocks.json)와 [종 자료](../data/species.defaults.json)를 사용한다. 구현 규칙은 [S4 계획](work/s4/plan.md)을 따른다.
S5에서는 전체 도감 목록과 등록 상태를 구분한다. 등록된 종을 빈 파티 칸에 소환하거나 교체한다. 진화 전후 종의 등록을 유지한다.
[스펙 미확정] 종별 기록, 동일 종 동시 소환, 재소환, 진화 승계와 반복 보상은 구현 전에 확정한다.

## 상점

현재 S4는 포켓몬·칸·민트·먹이·색 구매를 제공한다. 가격과 보상은 [상품 자료](../data/shop.json)를 따른다. 그림과 최신 상태를 확인한 뒤 거래를 저장한다.
S5는 구매와 사용을 분리한다. 구매한 도구와 알은 가방에 보관한다. 사용 시 대상 포켓몬을 고른다.
[스펙 미확정] 민트·진화의돌·랜덤알·이로치 도구는 기존 문서의 항목이다. 기능 자체의 채택부터 다시 확인한다. 무료 밥 주기는 기존 구현과 구분해서 유지한다.
[스펙 미확정] 상품 효과·가격·부화량과 기존 구매 권리의 이식은 [S5 계획](specs/s5.md)을 따른다. 현재 S4 코드와 재고를 먼저 삭제하지 않는다.

## 커맨드 처리기

현재 계약은 [공유 타입](../src/shared/types.ts)과 [등록 처리기](../src/main/commands.ts)를 따른다. 메뉴·CLI·mailbox는 같은 명령 처리 경로를 사용한다.
`feed`, `play`, `poke`, `evolve`, `party.show`, `party.hide`, `party.remove`, `pet.set`, `pet.look`, `shop.buy`, `agent.connect`, `agent.disconnect`, `settings.set`, `snapshot`, `quit`은 현재 계약이다.
S5의 `party.summon`, `party.dismiss`, `bag.use`, `egg.*`, `settings.open` 등은 제안이다. 현재 구현된 명령으로 안내하지 않는다.

`companion`은 포켓몬 인자를 받지 않는다. 빈 파티이면 선택창을 연다. 선택 취소와 저장 실패를 구분한다.
`pet.set`의 위치 변경은 저장에 성공한 뒤 성공으로 응답한다. 마우스 위치 변경도 같은 명령을 사용한다.
2026-09-21 확인: `pet.set size=3`은 `not-yet`으로 응답한다. 크기 필드의 저장과 크기 변경 명령의 구현은 다르다.
명령과 실제 앱을 연결한 검사 범위는 [실행 흐름 검수](work/runtime-e2e/record.md)를 따른다.

## 저장 v2와 S5 전환

현재 저장 계약은 [SaveV2와 Pet](../src/shared/types.ts)에 있다. `SaveV2.party`는 `Pet[]`다. `slots`는 1~6이다. 저장·복원 규칙은 [저장 모듈](../src/save/store.ts)과 [저장 규칙](../src/save/rules.ts)을 따른다.
`species`는 실제 종이다. `look`은 표시 그림이다. 개체 `id`는 진화 후에도 유지한다. writer 잠금과 mailbox를 유지한다.
S5는 도감 등록, 육성 기록, 파티 배치, 도구 재고, 알 상태를 분리한다. 박스와 별도 보관 개체 모델은 사용하지 않는다.
[스펙 미확정] 저장 버전과 정확한 필드·마이그레이션 절차는 아직 정하지 않았다. 기존 ID·기록·포인트·순서·표시·구매 권리를 보존해야 한다.
새 화면에서 별명·모습을 제거해도 기존 `nick`, `look`과 재고를 임의로 지우지 않는다. 원본 백업과 실패 복원을 먼저 설계한다.

## S5 디자인 시스템 v2

현재 시각 기준은 [Figma 00~05](https://www.figma.com/design/MA3K41Y6omAi5mRu6YDFly/pokebuddy?node-id=113-245)다. 2026-09-21 관측값은 [v2 검수](work/s5-design-system-v2/review.md)와 [자산 목록](work/s5-design-system-v2/evidence/inventory.json)에 있다.

| 항목 | 현재 기준 |
|---|---|
| 계층 | Foundations → Atoms → Molecules → Organisms → Templates → Screens. Screen은 Template 인스턴스로 구성한다. |
| 변수와 글꼴 | `PB / Primitive`, `PB / Color`, `PB / Dimension`의 변수 87개를 사용한다. `PB/Type/*` Inter 스타일은 9개다. 정의 수는 바인딩 완료를 뜻하지 않는다. |
| 색상 | 헤더와 카드는 `#FFFFFF`다. 본문은 `bg/canvas` `#F1F2EE`다. 강조는 `action/primary` `#0F766E`다. |
| 탭 | 파티 / 도감 / 상점 / 가방 / 설정. 내비게이션 Active는 5종이다. 도감·상점·가방·설정 본문은 아직 없다. |
| 내비게이션 | 사용자 수정 `114:967`을 따른다. 하단 테두리 1px와 선택 밑줄 60×2px를 구분한다. 10px padding·radius와 밑줄 x=10, y=31.5를 유지한다. |
| 화면 크기 | Screen은 720×780이다. 상세 Template `226:913`의 None·Confirm·Error는 펼친 콘텐츠 720×1030이다. 본문 638px 스크롤은 수정할 요구사항이다. |
| 모달 | Template에서 Modal Scrim `226:464`와 Confirm Dialog `164:238`을 조합한다. Screen에서 배경막과 확인창을 다시 그리지 않는다. |
| 그림 | `Portrait` `120:121`의 Artwork INSTANCE_SWAP을 사용한다. 실제 그림과 런타임 입력은 연결 전이다. |
| 상태와 숫자 | 숨김은 이미지 우측 위의 작은 닫힌 몬스터볼로 표시한다. 숫자는 콘텐츠로 다룬다. 친밀도나 크기별 숫자를 variant 축으로 늘리지 않는다. |

파티와 상세 기본·숨김·돌봄 성공·소환 해제 확인·저장 실패의 정적 화면 6개를 확인했다. 스크롤과 프로토타입 연결의 완료 근거로 사용하지 않는다.
열린 디자인 문제 12개는 [v2 피드백](work/s5-design-system-v2/feedback.md)에서 관리한다. Figma 수정은 이번 저장소 기록 정리에 포함하지 않았다.

## S5 설정창과 메뉴

파티는 2열×3행이다. 빈 칸과 잠긴 칸을 구분한다. 상세에서 숨기기·다시 표시와 소환 해제를 구분한다.
별명과 모습 선택은 제공하지 않는 기존 S5 설계다. 연결 설정은 설정 탭 안에 둔다.
[스펙 미확정] 성격·색상 변경의 도구 사용 방식은 채택 근거를 확인해야 한다. 명칭과 기능 출처는 [명칭 검수](work/s5-terminology/review.md)를 따른다.
우클릭 메뉴는 이름·상태, 밥 주기, 놀아주기, 설정, 종료를 제공하는 것으로 설계한다. 트레이 메뉴는 설정과 종료를 제공하는 것으로 설계한다. 현재 S4 메뉴의 구현 완료 상태와 구분한다.
전용 preload, contextIsolation, sandbox, IPC sender·최상위 frame 검사를 유지한다. 상세 수용 조건은 [S5 계획](specs/s5.md)을 따른다.

## 남은 결정과 검증

- [스펙 미확정] S5 육성 기록·저장 이식·상품·부화·동일 종 소환 규칙을 확정한다.
- [스펙 미확정] Electron 창 크기와 최소 크기·배율·스크롤 정책을 확정한다. Figma px를 검증 없이 DIP로 확정하지 않는다.

- [확인 필요] Codex·Gemini 토큰 읽기와 PMD 특수 폼 매핑을 확인한다.

현재 작업 순서와 검증 상태는 [진행 현황](progress.md)을 따른다. 과거 수치와 완료 기록은 [이력](history/2026-09.md)과 [S5 보관 자료](archive/s5-legacy/README.md)에서 확인한다.
