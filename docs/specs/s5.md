# S5 설정창 설계

갱신: 2026-09-21. 상태: Figma v2 반영 설계. 기능 구현 미시작.
범위: 현재 Figma 기준과 기능 계약을 정리한다. 게임 저장, 규칙표, 훅, 런타임은 변경하지 않는다.

[현재 Figma 검수](../work/s5-design-system-v2/review.md) · [현재 설계](../design.md) · [진행 현황](../progress.md) · [명칭 사전](../terms.md)

## 1. 목표와 결정

2026-09-21 정정: 에버스톤은 사용자 구상이 아니다. 기존 문서의 상품·부화 관련 사용자 결정 표기는 직접 근거가 확인되지 않았다. 아래 해당 내용은 기존 제안 기록이며, 기능 자체의 채택부터 재검토한다. [명칭 검수](../work/s5-terminology/review.md)를 따른다.

도감에 등록된 포켓몬을 골라 빈 파티 칸에 소환한다. 박스는 제공하지 않는다.
구매한 도구는 가방에 보관한다. 가방에서 사용한다.
별명과 외형만 바꾸는 모습 선택을 제거한다. 연결은 설정 안으로 옮긴다.
화면에서 '무대'를 쓰지 않는다. 숨김 상태는 이미지 우측 위의 작은 닫힌 몬스터볼로 나타낸다. 표시 조작은 상세의 숨기기·다시 표시를 사용한다.
'다른 색'은 '이로치'로 부른다. 실행 환경 명칭은 명칭 사전의 제안을 따른다.
도감은 전체 종을 다룬다. 지방 선택을 제공한다. 먹이 판매를 제거한다. 무료 밥 주기는 유지한다.

기존 문서에 기록된 설계와 제안:

- 박스를 제거한다. 빈 파티 칸과 교체에서 도감을 연다. 도감에서 등록된 종을 소환한다.
- 에버스톤은 S5 요구사항에서 제외한다. 사용자 요청으로 만들었던 기능처럼 기록하지 않는다.
- [스펙 미확정] 진화의돌 추가는 기존 문서의 제안이다. 사용자 채택 근거를 확인하지 못했다.
- 진화 전 종도 도감 등록을 유지한다. 등록되어 있으면 다시 소환할 수 있다.
- [스펙 미확정] 랜덤알과 작업 부화는 기존 문서의 제안이다. 기능 채택 여부를 다시 확인한다.

단일 진실 공급원(SSOT)은 다음과 같다.
이 문서는 상세 계약의 SSOT다. `design.md`는 결정의 SSOT다. `terms.md`는 명칭의 SSOT다. `progress.md`는 상태의 SSOT다.
기존 S4 기능은 아직 그대로 동작한다. 이 문서는 구현 완료 기록이 아니다.

## 2. 화면 구조

탭은 `파티 / 도감 / 상점 / 가방 / 설정`이다. Figma 내비게이션의 Active 5종을 기준으로 한다.
상단에는 보유 포인트를 표시한다. 흰 헤더·카드와 `#F1F2EE` 본문, `#0F766E` 강조색을 사용한다. `PB/Type/*`의 Inter 스타일을 사용한다.
Figma Screen은 720×780px다. 상세 Template은 전체 콘텐츠를 펼친 720×1030px다.
[스펙 미확정] Electron 창 기본·최소 크기와 크기 변경 정책은 구현 전에 확정한다. Figma px를 DIP로 그대로 확정하지 않는다.
[스펙 미확정] 작업 결과의 공통 표시 위치는 정하지 않았다. 현재 Template의 footer-space는 비어 있다. 상태별 안내와 오류 모달은 별도로 검수한다.

| 화면 | 구성 | 주요 동작 |
|---|---|---|
| 파티 | 2열×3행. 포켓몬·빈 칸·잠긴 칸 | 상세, 숨김 상태 확인, 도감에서 소환 |
| 상세 | 종 이름, 성격, 친밀도, 기분, 배고픔, 크기 | 돌봄, 진화, 교체, 소환 해제, 가방 |
| 도감 | 지방·등록 상태 선택, 검색, 목록, 상세 | 등록된 종 소환·교체, 획득 방법과 진화 조건 확인 |
| 상점 | [스펙 미확정] 기존 분류 제안: 포켓몬 / 알 / 도구 / 파티 칸 | 상품 구성 재검토 |
| 가방 | 도구 / 알, 수량과 설명 | 대상 선택 후 사용 / 부화 진행 확인 |
| 설정 | 일반 / 연결 | 표시, 동작, 언어, 시작, CLI별 연결 |

Tab과 방향키로 탭을 이동한다. Enter로 선택한다. Escape로 상세에서 돌아간다.
아이콘마다 툴팁과 접근성 이름을 제공한다. 색상만으로 상태를 구분하지 않는다.
상세 본문은 638px 높이에서 세로 스크롤한다. 헤더와 탭은 유지한다. 현재 05에는 스크롤 연결이 없으므로 구현 완료로 취급하지 않는다.
도감·상점·가방·설정 본문은 기능 계획이다. 현재 v2 Figma의 여섯 화면은 파티와 상세 상태에 한정된다.

## 3. 도감 등록과 파티 소환

도감 전체 목록에는 등록·미등록 종을 모두 표시한다. 목록에 보인다는 이유로 소환할 수 있지는 않다.
'등록'은 해당 종을 획득하여 소환할 수 있는 상태다. 스타터 선택, 구매, 부화, 진화로 등록한다.
상점 구매 조건 충족과 도감 등록은 별개다. 조건 충족만으로 유료 상품을 무료 소환하지 않는다.
[스펙 미확정] 기존 해금 자료를 새 등록으로 옮기는 기준은 이식 설계에서 확정한다.

빈 칸을 누르면 해당 칸을 지정한 도감을 연다. 기본 필터는 '등록'이다.
지방과 검색으로 종을 고른다. 'N번 칸에 소환'을 누른다. 완료하면 파티로 돌아간다.
상세의 '교체'도 해당 칸을 지정한 도감을 연다. 기존 포켓몬은 확정 전까지 유지한다.
취소, Escape, 다른 탭 이동은 파티를 변경하지 않는다. 취소하면 선택한 목적지를 해제한다.
일반 도감에서도 파티 칸을 선택해 등록된 종을 소환할 수 있다.
미등록 종은 획득 방법만 안내한다. 미등록 종의 소환은 막는다. 잠긴 칸은 대상 목록에서 제외한다.

| 동작 | 파티 칸 | 도감과 육성 기록 |
|---|---|---|
| 소환 | 등록된 종을 빈 칸에 배치 | 등록 유지 |
| 교체 | 선택한 종으로 배치 변경 | 이전 종 등록과 기록 유지 |
| 소환 해제 | 빈 칸으로 변경 | 등록과 기록 유지 |
| 숨기기 / 다시 표시 | 배치 유지, 표시만 변경 | 육성 유지 |

교체는 한 번의 저장 작업으로 처리한다. 그림이나 저장이 실패하면 이전 배치를 유지한다.
파티 칸은 최대 여섯 칸이다. 도감 등록 수와 독립적이다.
파티가 가득 차도 구매·부화·진화로 새 종을 등록한다. 소환은 이후에 할 수 있다.
진화 전 종도 등록을 유지하므로 외형 선택이나 별도 보관 화면 없이 다시 소환할 수 있다.
놓아주기와 영구 삭제는 제공하지 않는다.

[스펙 미확정] 종별 기록을 유지하는 것으로 제안한다. 재소환 시 그 기록을 복원하는 것으로 제안한다. 재소환으로 성격·친밀도·하루 상한을 다시 뽑거나 초기화하지 않는다.
[스펙 미확정] 동일 종 동시 소환 여부는 정하지 않았다. 이전 HTML은 중복을 막지만 현재 Figma 예시는 같은 종을 포함한다. 어느 예시도 게임 규칙의 확정 근거로 사용하지 않는다.
[스펙 미확정] 미소환 중에는 시간 기반 육성을 멈추는 것으로 제안한다. 숨긴 파티 포켓몬은 기존 육성을 유지하는 것으로 제안한다.
[스펙 미확정] 종별 기록·진화 기록 승계와 기존 중복 개체의 이식은 구현 전에 확정한다.
겹침과 소환 순서는 유지한다. 교체한 포켓몬은 새로 소환한 순서로 표시한다.

## 4. 상세와 진화

별명 입력과 모습 선택을 제공하지 않는다. 실제 종의 이름과 그림을 표시한다.
[스펙 미확정] 크기는 1~6단계로 제안한다. 조절을 완료하면 한 번 저장한다.
상세의 숨기기·다시 표시는 표시 여부만 바꾼다. '소환 해제'와 구분한다. 숨김 몬스터볼 마커 자체를 버튼으로 확정하지 않는다.
[스펙 미확정] 성격·색상 변경을 도구 사용으로 제공할지는 다시 검토한다. 대상 지정 흐름은 해당 기능이 채택된 경우의 제안이다.
밥 주기와 놀아주기를 유지한다. 먹이 상품과 효과 2배 안내는 제거한다.
에버스톤과 이에 따른 진화 방지는 사용자 요구사항으로 두지 않는다.

진화한 종을 도감에 등록한다. 이전 종의 등록도 유지한다.
이브이에서 블래키로 진화한 뒤에는 두 종 모두 도감에서 소환할 수 있다.
별도 보관 개체를 복제하는 이전 설계는 폐기한다.
[스펙 미확정] 종별 친밀도·성격·이로치·하루 상한의 승계 규칙은 정하지 않았다.
[스펙 미확정] 이미 등록된 종으로의 반복 진화 규칙은 정하지 않았다.
[스펙 미확정] 반복 진화의 보상 정책은 정하지 않았다.
현재 Figma는 정적 화면이다. 실제 진화·기록 승계·소환 처리는 구현하지 않았다.
[스펙 미확정] 진화의돌은 이전 문서의 상품 제안이다. 도구로 진화하는 기능 자체가 채택되었는지 확인해야 한다.
[스펙 미확정] 대상 종, 친밀도·시간 조건과의 관계, 가격, 소모 여부는 정하지 않았다.
모든 진화에 돌이 필요하다고 가정하지 않는다. 조건과 실패 이유를 표시한다. 메인 프로세스가 최종 검사한다.

## 5. 전체 도감과 지방

전국도감 전체 종을 표시한다. 상점 해금 규칙이 있는 종만으로 제한하지 않는다.
지방 선택과 이름·번호 검색을 함께 적용한다. 검색과 선택을 유지한다.
[스펙 미확정] 지방은 전체, 관동, 성도, 호연, 신오, 하나, 칼로스, 알로라, 가라르, 히스이, 팔데아로 제안한다.
[스펙 미확정] 분류는 최초 등장 지방 기준으로 제안한다. 여러 지역도감의 중복 등재와 구분한다.
폼은 해당 종 아래에 묶는다. 지방 폼을 번호 범위만으로 판정하지 않는다.
지역 정보가 없는 종도 '전체'에서 누락하지 않는다.
[확인 필요] 실제 매핑과 출처는 구현 전에 검증한다.
전체 목록 표시, 획득 조건 충족, 도감 등록, 소환 중 상태를 구분한다.
등록 필터는 전체 / 등록 / 미등록이다. 지방과 검색을 함께 적용한다.
획득 규칙이 없는 종에는 '획득 방법 준비 중'을 표시한다.
그림이 없으면 공통 자리표시자를 쓴다. 다른 종의 그림으로 대신하지 않는다.
보이는 카드와 선택한 종의 그림만 요청한다. 저작자와 라이선스를 표시한다.
이전 HTML의 도감은 일부 종 예시였다. 현재 v2의 도감 본문은 미제작이다. 전체 도감 데이터 연결은 구현 단계에서 처리한다.

## 6. 상점과 가방

[스펙 미확정] 아래 상품·효과·작업 부화는 기존 제안이다. 사용자 채택 근거를 확인하기 전까지 구현 지시와 인수 조건으로 사용하지 않는다. 상점·가방 탭의 존재는 개별 상품의 채택 근거가 아니다.

| 분류 | 구매 결과 | 대상 선택 |
|---|---|---|
| 포켓몬 | 도감에 해당 종 등록 | 없음 |
| 랜덤알 | 가방에 알 추가 | 없음 |
| 도구 | 가방 재고 증가 | 없음 |
| 파티 칸 | 다음 칸 해금 | 다음 칸 자동 지정 |

[스펙 미확정] 민트·진화의돌·이로치 도구는 검토 후보로 분리한다. 에버스톤은 채택 후보에 넣지 않는다. 먹이 상품 여부도 기존 문서의 기록만으로 사용자 결정이라 하지 않는다.
상점에서는 사용할 포켓몬을 고르지 않는다. 대상과 옵션은 가방에서 고른다.
민트는 가방에서 대상과 성격을 고른다. 이로치 도구도 가방에서 대상을 고른다.
[스펙 미확정] 현재 소환한 포켓몬만 도구 대상으로 제안한다. 파티가 비면 사용을 막는다. 이때 소환을 안내한다.
[스펙 미확정] 이로치 도구의 소모와 일반색 전환 규칙은 정하지 않았다.
가격이 정해지지 않았으면 화면에 '미정'으로 표시한다. 이 경우 구매를 막는다. 기존 가격 예시는 새 경제 규칙 확정이 아니다.
파티가 비어 있어도 도구를 구매할 수 있다. 가방이 비면 상점 이동을 제공한다.
사용 시 소유, 수량, 대상, 적용 가능 여부를 검사한다.
성공한 경우에만 수량을 차감한다. 저장이 실패하면 수량과 개체 상태를 함께 복원한다.

[스펙 미확정] 기존 랜덤알 제안은 구매 → 가방 → 부화 시작 → 작업 → 도감 등록 흐름이다. 작업 부화 자체를 확정 기능으로 취급하지 않는다.
[스펙 미확정] 이미 등록된 종의 재구매는 막는 것으로 제안한다. 이전 HTML의 동작이며 현재 Figma나 런타임 구현 완료 항목이 아니다.
[스펙 미확정] 알 중복 결과의 보상·대체 정책은 별도로 확정한다.
[스펙 미확정] 가격, 획득 범위, 확률, 중복 정책, 필요 작업량, 동시 부화 수는 정하지 않았다.
[스펙 미확정] 작업량은 기존 에이전트 활동 감지를 재사용하는 방향으로 검토한다. 시간·토큰 환산 비율은 별도로 확정한다.
작업 없는 대기 시간을 임의로 부화 작업량으로 계산하지 않는다.
부화 결과는 저장한다. 재시도나 재실행으로 다시 추첨하지 않는다.
구매 전에 획득 범위, 확률, 부화 조건을 확인할 수 있어야 한다.

## 7. 설정과 연결

설정 내부에 '일반 / 연결'을 둔다. 독립 연결 탭은 제거한다.
일반은 포켓몬 표시, 클릭 통과, 다른 앱에서도 표시, 잠들기 기준, 언어, 로그인 시 시작이다.
[스펙 미확정] 실행 환경 명칭은 '데스크톱에서 사용 / VS Code에서 사용 / 터미널 세션에서 사용'으로 제안한다.
내부 모드 식별자와 CLI 명령은 바꾸지 않는다. 모드를 고르는 새 옵션은 만들지 않는다.
데스크톱 실행은 항상 위 표시임을 설명한다. 세션 실행은 지원하는 표시 설정만 제공한다.
취침 대기 시간의 기본값은 5분이다. 선택지는 3분·5분·10분·15분·잠들지 않음이며 기존 제안이다. 성격·종 배율은 유지한다.
언어는 한국어와 영어다. 개발 실행의 자동 시작은 '앱 설치 후 사용 가능'으로 표시한다.

Claude Code, Codex CLI, Gemini CLI를 각각 연결·해제한다.
실제 훅 상태와 사용량 감지 상태를 구분한다. 화면 진입만으로 파일을 바꾸지 않는다.
미설치, 연결 안 됨, 연결됨, 확인 필요를 구분한다.
토큰을 지원하지 않으면 '작업 시간으로 적립'으로 표시한다. 0으로 가장하지 않는다.
CLI별 친밀도를 추정하지 않는다. 오늘 날짜의 파티 전체 작업 적립만 표시한다.
훅 원본 누락은 `hook-source-missing`으로 구분한다. 사용자 훅과 백업 규칙을 유지한다.

## 8. 저장과 명령

현재 [저장 타입](../../src/shared/types.ts)은 `SaveV2.party: Pet[]`에 개체를 직접 넣는다.
도감 등록과 재소환할 육성 기록을 분리한다. 박스·보관 개체 모델은 폐기한다.
[스펙 미확정] 저장 구조는 등록 종 목록, 종별 육성 기록, 파티 배치, 도구 재고, 개별 알과 부화 상태로 제안한다.
[스펙 미확정] 저장 v2 유지 여부, 정확한 필드, 마이그레이션 절차는 구현 전에 확정한다.
기존 ID, 친밀도, 성격, 파티 순서, 표시, 포인트, 구매 권리를 보존한다.
별명과 `look`은 새 화면에서 쓰지 않는다. 원본 백업 없이 지우거나 별도 개체로 변환하지 않는다.
[스펙 미확정] 기존 먹이 재고와 에버스톤·이로치 권리의 보존·보상 정책은 정하지 않았다. 자동으로 폐기하지 않는다.

| 계약 제안 | 역할 |
|---|---|
| `settings:snapshot` | 등록 상태, 육성 기록, 파티 배치, 가방, 도감, 가격, 연결, 설정 조회 |
| `party.summon` / `party.dismiss` | 등록된 종 소환·교체 / 소환 해제 |
| `party.show` / `party.hide` | 표시 변경 |
| `bag.use` | 도구와 대상 검사, 적용과 차감 |
| `egg.*` | 세부 부화 규칙 확정 후 정의 |
| `shop.buy` | 구매 종류별 도감 등록·가방·칸 반영 |
| `feed` / `play` / `evolve` | 돌봄과 진화. 진화 기록 계약 재설계 |
| `pet.set` | 크기. 별명·모습 UI 추가 없음 |
| `agent.connect` / `agent.disconnect` | 개별 연결 |
| `settings.set` / `settings.open` | 환경 설정 변경 / 창 열기 |

[스펙 미확정] 명령 이름은 제안이다. 기존 처리기와 mailbox를 함께 갱신한다.
요청 ID로 중복을 막는다. 응답이 불확실하면 결과부터 조회한다. 자동으로 재구매하거나 재사용하지 않는다.
[스펙 미확정] writer 교체와 응답 유실에도 구매·사용·부화가 중복되지 않는 영속 정책이 필요하다. 구현 전에 확정해야 한다.
메인 프로세스가 잔액, 대상, 소유, 그림, 진화 조건을 검사한다. 렌더러는 저장을 직접 다루지 않는다.
환경 설정은 잠금 안에서 최신 값과 변경 키를 병합한다. 실패 시 이전 값으로 복원한다.
자동 시작과 훅은 실제 상태를 재조회한다. 통계 저장 실패를 등록 실패로 가장하지 않는다.

## 9. 창과 보안

런타임마다 설정창 하나를 둔다. 재요청은 기존 창을 앞으로 가져온다.
우클릭 메뉴는 개체 상세를 연다. 트레이 아이콘은 마지막 탭을 연다. `pokebuddy settings`는 실행 중인 앱의 창을 연다.
앱이 없으면 `pokebuddy companion` 실행을 안내한다. 임의로 새 게임을 만들지 않는다.
VS Code 확장 명령은 해당 창으로 요청한다. 숨김·클릭 통과에서도 복구 경로를 유지한다.
설정창을 닫아도 포켓몬과 육성은 계속 실행한다.
포켓몬 표시 창과 설정창은 별개다. 설정창은 클릭 통과와 항상 위 설정을 물려받지 않는다.
contextIsolation과 sandbox, 전용 preload, IPC sender·최상위 frame 검사를 유지한다.
키·값·명령을 검증한다. 그림 요청은 종·폼 키만 받는다. 임의 경로나 URL은 받지 않는다.
원격 탐색과 새 창을 막는다. 저작자 링크는 허용 목록에 있는 것만 외부로 연다.
보이는 동안 최대 초당 한 번 상태를 갱신한다. 성공 직후에는 즉시 갱신한다.
닫거나 숨기면 구독·타이머를 해제한다. 탭·검색·선택·스크롤·포커스를 유지한다.

## 10. 구현 순서와 위험

1. 미정 게임 규칙, 명칭, 저장 이식 정책을 확정한다.
2. 저장·명령 계약과 마이그레이션을 설계한다. 이를 검사한다.
3. 도감 등록·소환·가방 처리기, 거래 원자성, 중복 방지를 구현한다.
4. 전체 도감·지방 자료, 상품·알 규칙을 연결한다.
5. 설정창과 전용 preload를 만든다. 다섯 탭을 연결한다.
6. CLI·확장 진입, 메뉴, 언어, 연결을 검사한다.
7. 남은 JS를 TS로 이식한다. UI 검사와 이식 회귀는 나눈다. 설치 전 `postinstall.js`는 유지한다.

## 11. 인수 기준

상품 사용·작업 부화 관련 기준은 해당 기능 채택 후에만 적용하는 기존 초안이다. 에버스톤은 제외한 요구사항을 다시 추가하지 않기 위한 확인 항목이다.

- 파티 0·1·6마리, 빈 칸·잠긴 칸·숨김을 구분한다. 숨김 마커와 표시 조작에 접근성 이름이 있다.
- 빈 칸에서 등록 도감을 연다. 해당 칸에 소환한다. 미등록 종·잠긴 칸의 소환을 막는다.
- 교체 취소와 저장 실패는 파티를 유지한다. 소환 해제와 재소환은 등록·육성 기록을 보존한다.
- 일반 도감 진입 시 이전에 취소한 목적지 칸을 재사용하지 않는다.
- 진화 전후 종을 모두 도감에서 소환한다. 반복 진화와 등록 보상 악용을 막는다.
- 파티가 가득 차도 구매·부화 결과를 도감에 등록한다.
- 박스, 별명, 모습, 먹이 판매, 에버스톤, 독립 연결 탭이 없다.
- 지방과 검색을 함께 적용한다. 결과 0건을 안내한다. 없는 획득 규칙을 해금으로 표시하지 않는다.
- 구매 시 대상 선택이 없다. 사용 실패 시 재고와 개체 상태를 보존한다.
- [스펙 미확정] 작업 부화를 채택하면 재시도로 결과가 바뀌지 않는지 검사한다.
- 마이그레이션·실패 복원·writer 경합·중복 요청 검사를 통과한다.
- 키보드, 한영 문구, 720×780 기준 화면, 확정한 최소 창 크기, 100·125·150% 배율을 검사한다.
- 상세 하단의 성장·소환 해제에 스크롤로 도달한다. 모달에서 배경과 상태를 구분한다.
- 친밀도 값과 막대를 연결한다. 숫자별 variant를 만들지 않는다.
- 여섯 상태의 이동·복귀·실패 조작을 연결한다. 숨김 설명과 실제 종 타입을 일치시킨다.
- 실제 기능은 임시 HOME으로 검사한다. 실제 저장, 훅, 자동 시작은 변경하지 않는다.

## 12. 미정 사항과 검증 상태

[스펙 미확정] 종별 육성·재소환·진화 승계·보상 규칙, 진화의돌 조건, 알 경제·작업량, 이로치 도구 효과, 기존 권리 이식은 반드시 확정해야 한다.
[스펙 미확정] 실행 환경 명칭, 지방 분류 기준, 동일 종 동시 소환, 미소환 중 육성은 제안 단계다. 다섯 탭의 시각 배치는 v2를 따른다.
이번 단계는 설계까지만 진행한다. 기능 구현과 실제 저장 검증은 미시작이다.

현재 시각 검증은 [v2 검수](../work/s5-design-system-v2/review.md)에 남긴다. 열린 디자인 항목 12개는 [v2 피드백](../work/s5-design-system-v2/feedback.md)을 따른다.
