## 기존 구현 검토

저장, writer/reader 전환, mailbox, 명령 처리, 에이전트 사용량, 무대 갱신, 움직임, 렌더러 계약을 확인했다.
기존 자체 확인 6벌은 통과했다. 그러나 아래 경계 사례를 놓치고 있었다.

| 중요도 | 문제와 영향 | 수정·회귀 검사 |
|---|---|---|
| 높음 | 같은 프로세스가 같은 밀리초에 같은 명령을 보내면 요청과 회신 경로가 겹쳐 요청 하나가 사라진다 | 요청 이름에 순번을 추가했다. 고정 시계로 두 feed 요청을 동시에 보내 서로 다른 대상의 회신을 확인했다 |
| 높음 | usage 파일을 잠깐 못 읽으면 seen에서 사라진다. 복구 시 이전 사용량을 다시 센다 | 빠진 세션의 기준점을 유지한다. 공백, 동일 누적량, 새 증분 순서로 검증했다. 음수·무한대 토큰도 제외했다 |
| 높음 | writer 여부를 메모리 플래그만으로 판단하면 잠금 소유권을 잃어도 저장할 수 있다 | isWriter·persist에서 실제 lock을 확인한다. 다른 살아 있는 PID로 교체한 뒤 저장 원본이 유지되는지 검증했다 |
| 보통 | 같은 id의 look을 바꿔도 이전 그림, 몸 크기, 움직임을 계속 사용한다 | 새 그림과 시트를 로드하고 들기 상태를 해제한다. 실제 createStage에 가짜 창과 그림 로더를 넣어 교체를 검증했다 |

이 결과는 확인한 경로에 대한 검토다. 모든 플랫폼 동작의 무결성을 보장하지 않는다.
기존 save.lock의 오래된 잠금 회수는, 여러 프로세스가 정확히 동시에 실행되는 상황에서, 아직 검증하지 않았다.

## S3 구현

- 성격 축은 걷는 속도, 쉬는 시간, 제자리 동작, 수면, 만지기 반응에 영향을 준다.
- 사교성 축은 다른 마리에게 다가가거나 피하는 정도를 정한다.
- 대담함 축은 커서에 다가가거나 피하는 정도를 정한다.
- 변덕 성격을 가진 마리는 90초 주기마다 10초 동안 성격 축 하나가 바뀐다.
- 수면 시점은 기존 motion 모듈의 시계가 정한다. 수면 판정은 종의 sleepiness 값을 반영한다.
- 마리마다 배고픔, 기분, 친밀도 값을 따로 관리한다.
- 마리마다 하루 친밀도 상한을 따로 둔다.
- 날짜 전환을 처리한다.
- 연속 교감 일수와 하루 첫 교감 포인트 지급 기능을 구현했다.
- 시작 기분은 종의 moodBase 값이다.
- 친밀도는 감소하지 않는다.
- 켜 두기와 작업량에 따른 친밀도 적립은 화면에 나온 마리에게만 적용한다.
- 배고픔과 기분 변화는 숨긴 마리에게도 적용한다.
- 꺼 둔 시간은 적립하지 않는다.
- 절전 등으로 틱 간격이 길어지면 5초까지만 인정한다.
- 토큰 값은 훅이 기록한 누적 사용량의 증분이다.
- 작업 기록에 usage 값이 있으면 작업 시간으로 대체 적립하지 않는다.
- Codex와 Gemini 전용 토큰 리더는 아직 구현하지 않았다. 이 두 CLI는 대신 작업 시간을 사용한다.
- feed·play·poke 명령을 dispatcher와 mailbox에 연결했다.
- writer 역할을 가진 프로세스만 상태를 저장한다.
- 저장 시점은 15초 주기, 돌봄 직후, 정상 종료, 역할 양도 네 가지다.
- 돌봄 직후 저장에 실패하면 메모리상의 효과를 되돌린다. 그 뒤 save-failed 값을 반환한다.
- 우클릭 메뉴 첫 줄은 배고픔, 낮은 기분, 다음 진화까지, 기분 순서로 해당하는 것 하나를 보여준다.
- 밥과 놀기 버튼에는 재사용 대기 이유를 표시한다.
- 밥 동작은 마리가 열매로 이동해 먹는 동작이다.
- 놀기 동작은 12초 동안 커서를 따라가는 동작이다.
- 필요한 동작 그림이 없으면 보유한 Nod, Idle 등의 그림으로 대체한다.
- CLI의 status 명령에 배고픔과 기분 표시를 추가했다.
- 세션 샌드박스 모드는 게임 저장과 포인트 적립을 지원하지 않는다.
- 성격 목록의 저장 모듈 사본을 삭제했다.

## 초기값

주요 값은 사용자가 2026-09-17에 승인했다. 종과 성격에 따른 배율은 별도로 곱한다.

| 항목 | 값 |
|---|---|
| 켜 두기 | 시간당 친밀도 +6 |
| 토큰 | 1천 토큰당 친밀도 +1, 1만 토큰당 포인트 +1 |
| 토큰을 읽지 못하는 작업 | running 시간당 친밀도 +12 |
| 하루 상한 | 마리마다 친밀도 200, 토큰 포인트는 저장 전체 50 |
| 배고픔 | 시간당 +10, 밥 −40 |
| 밥 / 놀기 | 친밀도 +8 / +6, 기분 +10 / +12, 각각 10분 대기 |
| 찌르기 / 턴 완료 | 친밀도 +1·기분 +2, 찌르기 보상 하루 10회 |
| 첫 교감 | 연속일 ×2 포인트, 최대 7일분. 토큰 포인트 상한과 별도 |
| 기분 감소 | 배고픔 70 이상: 시간당 −6, 1시간 돌봄 없음: 시간당 −3 |
| 활동성이 높은 / 낮은 마리 | 걷기 1.2 / 0.8배, 쉬는 시간 0.8 / 1.2배 |

`src/state/rules.ts`, `src/motion/params.ts`, `src/dex/natures.ts`에 규칙을 모았다.
밥·놀기 대기와 기분 세부값은 구현 초기값이다. 이 값은 사용해 본 뒤 조정할 대상이다.
캐시 읽기 토큰은 기존 0.1 가중치를 유지한다.

## 확인과 남은 실기

- 타입 검사, 빌드, 자체 확인 7벌을 확인했다. 상태 테스트는 시간 적립, 토큰 공백, 재시작, 상한, 숨김, 실패·턴 중복, 돌봄, 날짜·스트릭, 저장 왕복, 성격별 접근·회피를 확인한다.
- 무대 테스트는 그림 교체, 먹이 이동·제거, 커서 따라가기, 잠금 상실, mailbox 돌봄 왕복, 저장 실패 롤백을 포함한다. Windows에서는 기존 mac용 가짜 anchor 실행 테스트를 건너뛴다.
- 숨긴 Electron 창에서 로컬 mock 시트 3종을 로드했다. 캔버스 픽셀과 화면 캡처를 확인했다. `dist/tools/smoke-renderer.js`를 사용했다. 임시 사용자 폴더만 사용했다. 실제 게임 저장을 만들거나 수정하지 않았다.
- **미확인:** 실제 PMD 그림을 쓰는 Windows 드래그·우클릭·클릭 통과, 125%/150% DPI, 6마리 CPU/GPU, macOS 회귀 실기를 아직 확인하지 않았다. mock 렌더링 검사는 이를 대신하지 않는다.
- 토큰 기준점은 일시적인 읽기 실패와 삭제를 구분할 수 없어 보존한다. 장기 사용 시 오래된 세션의 기준점 정리 정책을 추가할 수 있다.

다음 단계는 S2/S3 실기 결과를 반영한 뒤 진행하는 S4(해금·상점·진화)다. S5의 설정창과 메뉴 최소화는 아직 구현하지 않았다.
