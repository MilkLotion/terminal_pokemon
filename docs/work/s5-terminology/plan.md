# S5 명칭과 기능 출처 정정

## 2026-09-21 — 요청 #119 후속 삭제 설계

출처: 사용자는 이번 대화에서 #119 항목의 기능과 명칭을 검색에도 남지 않게 제거하라고 지시했다.
범위는 상품, 메뉴, 명령 분기, 진화 제한, 저장 필드, 언어 문구, 검사와 과거 문서다.
이 지시는 해당 항목의 과거 기록 보존 지침보다 우선한다. 삭제 기록에도 원래 명칭을 반복하지 않는다.
실제 사용자 저장 파일과 Git 이력은 변경하지 않는다. 다른 상품과 기존 문서 정리 변경은 유지한다.
위험은 진화 조건 회귀와 저장 정규화 회귀다. 남은 조건과 데이터 보존을 검사한다.
수용 조건은 작업 트리 검색 결과 0건, 빌드 통과, 저장·도감·상태·상점 검사 통과다.
문서 의미 검수, 문서 구조 검사, 공백 검사도 수행한다.

## 2026-09-21 — 용어사전 후속 정리 설계

사용자 요청: “지금까지 작업들 기반으로 용어사전 정리부터 해보고 싶은데”. 출처는 이번 대화다.
목표는 기존 용어의 의미와 적용 범위를 찾기 쉽게 정리하는 것이다.
범위는 [용어사전](../../terms.md), [S5 기능 계약](../../specs/s5.md)의 명칭 상태, 관련 기록과 현황이다.
결정 기준은 [현재 설계](../../design.md)다. 상태 기준은 [현황](../../progress.md)이다.
현재 개념은 [저장 타입](../../../src/shared/types.ts)과 [상태 규칙](../../../src/state/rules.ts)으로 대조한다.
앱 코드, 저장 데이터, Figma 원본은 변경하지 않는다. S5 기능 구현은 미시작이다.

위험: 기존 설계의 명칭을 정리하면서 사용자 승인이나 구현 완료로 오인할 수 있다.
현재 구현, 기존 설계, 미확정 제안, 제외 항목을 구분한다. 원래 발언이 없으면 승인 근거를 추가하지 않는다.

수용 조건:

- 파티와 파티 칸, 해금과 도감 등록, 숨기기와 소환 해제를 구분한다.
- 사용자 용어와 내부 자산 이름을 분리한다.
- 미확정 상품과 실행 환경 명칭의 상태를 유지한다.
- 각 용어 묶음에 출처를 연결한다.
- 변경 문장을 의미 검수한다. 문서 검사와 공백 검사를 실행한다.

## 이전 정정 설계

날짜: 2026-09-21. 상태: 문서 정정 완료. 미확인 기능의 채택은 미정이다. 기능 구현 미시작.

## 목표와 범위

기존 구현과 문서에 등장한다는 이유로 사용자 결정으로 취급한 내용을 바로잡는다.
명칭 교체와 기능 채택을 구분한다. 다른 포켓몬 용어로 자동 치환하지 않는다.
현재 명칭 사전·S5 계획·설계·현황과 과거 기록의 안내를 정정한다. 실행 코드와 저장 데이터는 변경하지 않는다.

## 기준과 위험

- 현재 사용자 정정을 가장 먼저 적용한다.
- 두 공유 대화의 사용자 발언과 기존 코드·문서를 구분해서 확인한다.
- Figma 관측 목록은 일부 속성만 담는다. 목록에 문자열이 없다는 이유로 Figma 전체에서 없다고 단정하지 않는다.
- 민트·진화의돌·랜덤알·이로치 도구도 직접 채택 근거가 확인되지 않으면 확정 명칭으로 안내하지 않는다.

## 수용 검사

- 미확인 상품의 명칭과 효과를 확정 목록에서 분리한다.
- 과거 사용자 결정 표기는 날짜가 있는 정정 기록과 연결한다.
- 문서 상대 링크와 `git diff --check`를 확인한다.
- 코드 변경이 없으므로 빌드·린트·런타임 검사는 실행하지 않는다.
