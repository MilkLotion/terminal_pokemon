# 기존 실행 흐름 재검수

갱신: 2026-09-21
상태: 실행 흐름 재검수와 발견한 결함 수정 완료. 플랫폼 전체 검수는 미완료.

## 설계

사용자 요청: 기존 구현의 잘못된 실행 흐름을 재검수한다. `pokebuddy companion`이 포켓몬을 요구했던 사례를 기준으로 확인한다.
목표: 명령 입력부터 첫 선택·복원·조작·종료까지 연결해서 검사한다. 전체 재설계가 필요한지 근거로 판단한다.
범위: CLI 입구, 첫 실행, 기존 파티, 명령 전달, 실패·종료, 관련 회귀 검사.
최초 검수의 제외 범위: S5 상품 채택, Figma 수정, 설치·훅 변경, 사용자 저장 변경, 커밋·푸시.
2026-09-21 후속 요청: 다른 PC에서 이어갈 수 있도록 문서를 정리하고 기존 변경을 커밋한다. 원격 푸시는 이번 후속 작업에 포함하지 않는다.

수용 조건:

- `companion`에는 포켓몬 인자가 필요하지 않다.
- 포켓몬 인자의 모든 표기 방식에 같은 규칙을 적용한다.
- 잘못된 종료 인자나 도움말 요청으로 앱을 종료하지 않는다.
- 첫 실행은 선택창을 제공한다. 재실행은 저장된 파티를 복원한다.
- 기존 명령의 상태 변경과 저장을 임시 HOME에서 확인한다.
- 실행 실패와 정상 종료를 구분한다.
- 검사 범위와 미실행 환경을 기록한다.

검사 데이터는 임시 HOME·USERPROFILE·TEMP 아래에 둔다. 현재 소스의 검증에 필요한 빌드만 실행한다. 실제 저장·훅·자동 시작을 변경하지 않는다.

## 작업

### 발견 사항과 수정

| 중요도 | 발견 사항 | 수정과 근거 |
|---|---|---|
| 높음 | `companion stop --help`와 잘못된 추가 인자가 앱을 종료했다. | [인자 파서](../../../cli/args.js)에서 도움말과 인자 오류를 먼저 판정한다. |
| 높음 | 위치 저장에 실패해도 `pet.set`이 성공으로 응답했다. 메모리 위치도 바뀌었다. | [명령 처리](../../../src/main/commands.ts)에 저장 실패 복원을 적용했다. [자체 검사](../../../src/tools/selftest-stage.ts)에서 수정 전 실패와 수정 후 통과를 확인했다. |
| 보통 | `--pet eevee`는 거부했지만 `pet=eevee`와 `pokemon=eevee`는 허용했다. | 포켓몬 옵션의 별칭과 표기 방식에 같은 규칙을 적용했다. 동반자는 `buddy`와 `click`만 받는다. |
| 보통 | `--buddy --help`에서 다음 옵션을 값으로 소비했다. | 옵션 값의 누락을 먼저 검사한다. |
| 보통 | 부모의 `POKEBUDDY_SLUG`가 첫 선택창을 생략하게 했다. 세션의 크기 설정도 상속했다. | [동반자 실행](../../../cli/run.js)에서 세션용 포켓몬·크기·표시 환경변수를 제거했다. |
| 보통 | CLI는 저장 파일의 존재만으로 첫 실행을 판정했다. 앱은 빈 파티에도 선택창을 열었다. | CLI도 저장 내용으로 판정한다. CLI의 조회는 `repair: false`를 사용한다. |
| 보통 | 창을 만들면 그림과 명령의 준비 전에 실행 성공을 알릴 수 있었다. | [앱 초기화](../../../src/main/app.ts)가 끝난 뒤 `ready`를 기록한다. |
| 보통 | 첫 선택창을 닫으면 실행 실패로 표시했다. 첫 저장 실패는 선택 취소와 같은 이유로 기록했다. | `starter-cancelled`와 `save-failed`를 구분한다. 취소는 종료 코드 0을 반환한다. 저장 실패는 종료 코드 1을 반환한다. |

마우스로 위치를 옮기는 경로도 `pet.set`에 연결했다. 실패하면 저장된 파티 상태로 화면을 갱신한다.
Windows의 실행 도우미에는 `-WindowStyle Hidden`을 적용했다. 앱 창의 표시 여부는 Electron이 관리한다.

현재 소스에서 `pokebuddy companion`만 입력할 때 포켓몬을 요구하는 현상은 재현되지 않았다. 대신 포켓몬 옵션을 우회해서 받는 경로를 확인했다.
현재 명령의 PowerShell·cmd 진입점은 이 저장소의 파일을 가리켰다. 사용자가 과거에 본 오류의 실행 버전은 확인하지 못했다.

### 회귀 검사 연결

- [CLI 검사](../../../scripts/selftest-cli.cjs)를 `npm run selftest`에 추가했다.
- [실제 앱 E2E](../../../scripts/e2e-companion.cjs)는 `npm run test:e2e`로 실행한다.
- [관측 도우미](../../../scripts/e2e/companion-observer.cjs)는 선택창의 실제 DOM을 클릭한다. 앱의 저장·IPC·그림 로더는 교체하지 않는다.

E2E는 시험용 창을 숨긴다. 그림을 받으므로 네트워크가 필요하다. `HOME`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `TEMP`, `TMP`는 시험용 경로를 사용한다.
검사가 끝나면 시험용 동반자를 종료한다. 진단 파일은 임시 폴더에 남긴다. 실제 사용자 저장과 훅은 변경하지 않았다.

### 다른 PC의 재개 절차

저장소는 `MilkLotion/terminal_pokemon`이다. 작업 브랜치는 `main`이다.
이번 변경의 커밋 제목은 `fix: [동반자] 실행 흐름 오류 수정과 세션 인계 정리`다. 정확한 해시는 아래 명령으로 확인한다.

```text
git status --short
git log -5 --oneline
git log -1 --format="%h %s" --grep="실행 흐름 오류 수정과 세션 인계 정리"
```

원격으로 받을 때는 먼저 이 커밋이 원격 저장소에 전달됐는지 확인한다. 다른 PC에 로컬 변경이 있으면 해당 변경을 보존한 뒤 동기화한다.
동기화할 때 이 PC의 `node_modules`, `dist`, 임시 HOME을 복사하지 않는다. 새 PC에서 의존성과 실행 파일을 준비한다.

저장소 루트에서 Node.js `>=22.12`와 npm을 사용한다. 의존성을 처음 준비할 때는 아래 명령을 실행한다.

```text
node --version
npm ci
```

`npm ci`는 Electron 다운로드와 TypeScript 빌드를 실행한다. macOS에서는 Swift 컴파일러가 있으면 창 추적 도우미도 준비한다. 새 PC에서의 설치 성공 여부는 별도로 확인한다.

실행 흐름을 다시 검사할 때는 아래 명령을 사용한다.

```text
npm run selftest
npm run test:e2e
node scripts/check-docs.cjs
git diff --check
```

`selftest`에는 CLI 회귀 검사가 포함된다. `test:e2e`는 소스를 빌드한 뒤 임시 HOME에서 실제 Electron을 실행한다. 그래픽 세션과 그림 다운로드가 가능한 네트워크가 필요하다.
문서만 수정한 경우에는 `node scripts/check-docs.cjs`와 `git diff --check`만 실행한다. 새 PC의 macOS 검사는 아직 통과한 것으로 간주하지 않는다.
E2E가 출력한 임시 경로에는 `cli.jsonl`, `events.jsonl`, `result.json`이 남는다. 저장소의 [결과 요약](evidence/windows-companion.json)에 있는 `dir`은 이전 PC의 경로다. 새 PC에서 접근할 경로가 아니다.

읽을 자료와 다음 산출물:

| 순서 | 자료 | 이어서 할 일 |
|---|---|---|
| 1 | [현재 설계](../../design.md), [S5 계약](../../specs/s5.md) | 확정 기능과 제안을 구분한다. |
| 2 | [명칭 사전](../../terms.md), [명칭 정정](../s5-terminology/review.md) | 에버스톤을 S5 요구사항으로 복원하지 않는다. 다른 미확인 상품도 자동 채택하지 않는다. |
| 3 | [Figma 검수](../s5-design-system-v2/review.md), [열린 항목](../s5-design-system-v2/feedback.md) | 최신 Figma를 다시 관측한다. 열린 항목의 현재 상태를 확인한다. |
| 4 | [실제 앱 E2E](../../../scripts/e2e-companion.cjs), [명령 처리](../../../src/main/commands.ts) | 기존 실행 검사를 유지한다. 새 S5 흐름의 수용 조건을 추가할 위치를 정한다. |

첫 S5 산출물은 흐름별 계약 표로 제안한다. 각 행에 진입점, 대상 필요 여부, 실행 명령, 변경할 저장 값, 성공 결과, 취소 결과, 실패 복원, 재실행 결과를 적는다.
설정창 열기처럼 대상이 필요 없는 동작과 개체 조작을 구분한다. 빈 파티에서도 대상이 필요 없는 화면에 진입할 수 있어야 한다.
확정 전의 상품·육성·저장 이식 규칙은 `[스펙 미확정]`으로 남긴다. `pet.set size=3`을 기존 완료 기능으로 가정하지 않는다.
이 계약 표는 [S5 계약](../../specs/s5.md)에 반영한다. 후속 구현 기록은 [문서 작업 절차](../../contributing/workflow.md)의 위치 규칙을 따른다.

## 검수

환경: Windows, Node.js 22.16.0, 저장소에 설치된 Electron 44.4.0.

| 실행 | 범위 | 결과 |
|---|---|---|
| `npm run build` | 현재 소스의 메인·렌더러 컴파일 | 통과 |
| `node scripts/selftest-cli.cjs` | 파서와 Node·PowerShell·cmd 진입점 | 33개 통과 |
| `node dist/tools/selftest-<이름>.js` | `save`, `dex`, `agents`, `follow`, `motion`, `stage`, `state`, `shop` 순서로 실행 | 8벌 통과. `stage`는 112건 통과 |
| `node scripts/e2e-companion.cjs` | 실제 CLI부터 Electron 종료까지 | 아래 9개 흐름 통과 |
| `electron dist/tools/smoke-renderer.js` | 숨긴 창의 그리기·겹침·투명 영역·히트·우클릭. 로컬 그림 fixture 사용 | 통과. 그려진 픽셀 7,524개 |
| `node scripts/check-docs.cjs` | 문서 구조와 참조 | 문서 45개·파일 링크 337개·JSON 5개 통과 |
| `git diff --check` | 변경 파일 공백 | 통과 |

자체 검사는 임시 HOME에서 실행했다. Windows에서는 `selftest-stage`의 가짜 Unix anchor 실행 검사가 건너뛰어진다.
렌더러 검사는 Electron 프로세스의 종료 코드를 기다려 확인했다. 캡처의 수동 시각 검수는 실행하지 않았다.

실제 앱 검사 결과는 [Windows E2E 결과](evidence/windows-companion.json)에 보관했다.

1. 포켓몬 인자 없이 선택창을 연다. 부모의 포켓몬 환경변수가 선택을 생략하지 않는다.
2. 선택창에서 이브이를 고른다. 실제 저장과 앱 준비를 확인한다.
3. 중복 실행은 기존 앱을 유지한다. CLI의 `snapshot`이 실제 mailbox에서 응답을 받는다.
4. 크기 변경은 `not-yet`으로 응답한다. 저장된 크기는 유지한다.
5. 위치 변경을 저장한다. 숨기기·다시 표시·밥 주기를 처리한다.
6. 종료 후 같은 개체와 위치를 복원한다. 선택창은 다시 열지 않는다.
7. 빈 파티를 저장한 상태에서 선택창을 연다. 선택창을 닫아도 저장 내용은 유지한다.
8. 선택 중 `companion stop`을 실행한다. 정상 종료하며 저장 내용을 유지한다.
9. 첫 포켓몬의 저장 실패를 재현한다. 선택 취소와 구분하며 실행 성공을 알리지 않는다.

검사 도우미 작성 중 발생한 실행 경로·PowerShell 인용·Electron 초기화 시점 문제를 수정했다. 위 표는 수정 후 실행 결과다.
의미 검수: 사용자 요청과 구현 관측을 구분했다. 완료 범위와 미실행 검사를 구분했다. 현재 문서는 이 기록을 링크한다.

## 피드백과 수정

2026-09-21 정정: 앞선 설명에서 마리별 크기 변경을 기존 기능처럼 다룬 부분은 잘못됐다. 크기 필드는 저장하지만 `pet.set size=3`은 미구현이다. 현재 설계·현황·설명서를 정정했다.

이번 범위에서 발견한 위 결함은 수정했다. 사용자 요청을 근거로 S5 상품이나 새 게임 규칙을 추가하지 않았다. 최초 재검수 완료 시점에는 커밋·푸시를 실행하지 않았다.
후속 인계 작업은 기존 수정·검사 스크립트·문서를 같은 커밋에 포함한다. 인계 문서 작업에서는 런타임 코드를 추가 변경하지 않았다. 이전 런타임 검사 결과를 유지하고 문서 검사를 다시 실행한다.
인계 문서 검사: 문서 45개·파일 링크 352개·JSON 5개를 통과했다. `git diff --check`도 통과했다.
인계 문장의 의미 검수: 이전 PC의 결과와 새 PC에서 실행할 절차를 구분했다. 커밋 전달 조건과 임시 경로의 수명을 명시했다. 미확정 S5 기능을 완료 기능으로 기록하지 않았다.

재설계 판단: 기존 런타임 전체를 교체할 근거는 이번 검수에서 찾지 못했다. 검증한 흐름은 기존 구현을 수정해서 통과했다.
[스펙 미확정] S5는 사용자 흐름별 성공·취소·실패 결과를 먼저 정의하는 방식을 제안한다. 각 화면의 명령·저장 계약과 E2E 수용 조건을 연결한다. 화면 구현은 해당 계약 다음에 진행한다.

남은 검수:

- 실제 마우스 끌기와 Windows 배율은 미실행이다. 마우스 위치 저장 경로의 연결은 코드로 확인했다.
- macOS, 다중 화면, 동시 실행 경쟁 조건은 미실행이다.
- 실제 VS Code 다중 창과 에이전트 세션 연결은 미실행이다.
- 설치·패키징·자동 시작은 미실행이다.
- S5 설정창의 E2E는 미실행이다. 해당 화면은 아직 구현하지 않았다.

이번 결과는 저장소 전체의 모든 분기나 Figma 일치성을 검수했다는 뜻이 아니다. S5의 열린 디자인 항목과 미확정 상품은 기존 기록에서 계속 관리한다.
