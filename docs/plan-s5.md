# S5 설정창 설계

작성일: 2026-09-18. 기준 커밋: `85daaa7` (`feat: S4`).
범위: **설계만 진행한다. 기능 코드는 변경하지 않는다.**
사용자 지시: 계획 → 설계 → 작업 → 검수 → 피드백 → 수정. 이번 요청은 설계에서 멈춘다.

[화면 시안](s5-preview.html) · [현재 설계](design.md) · [진행 현황](progress.md)

## 1. 목표와 경계

설정창 하나에서 파티, 도감, 상점, 연결, 설정을 조작한다.
메뉴에는 자주 쓰는 돌봄과 설정창 진입만 남긴다.
S4의 가격, 진화 문턱, 보상, 저장 v2를 재사용한다.
포켓몬 겹침과 소환 순서는 바꾸지 않는다.

다음 항목은 이번 설계의 새 제안이다. 구현 완료나 사용자 확정으로 취급하지 않는다.

- 창 기본 크기: 1040×760 DIP. 최소 크기: 800×620 DIP.
- 별명: 공백을 정리한 뒤 최대 20개 표시 문자. 빈 값은 종 이름으로 복원.
- 크기: 1~6단계. 실제 배율은 기존 그림 크기 제한을 적용.
- 잠들기 기준: 기본 5분. 선택지는 3분, 5분, 10분, 15분, 잠들지 않음.
- 표시와 고스트 설정은 실행 모드별로 저장. 언어와 수면 기준은 공통으로 저장.
- 배포 앱에서 자동 시작을 지원. 개발 실행에서는 선택을 막고 이유를 표시.

수면 시간은 중립 기준이다. 기존 성격과 종의 수면 배율을 곱한다.
화면에는 `잠들기 기준`과 `실제 시간은 성격에 따라 달라집니다.`를 함께 표시한다.

## 2. 화면 구조

상단에는 앱 이름, 현재 탭, 보유 포인트를 둔다.
탭 순서는 `파티 / 도감 / 상점 / 연결 / 설정`으로 고정한다.
본문 아래에는 현재 상태와 작업 결과를 한 줄로 표시한다.

| 화면 | 구성 | 주 조작 |
|---|---|---|
| 파티 | 2열×3행 카드. 마리, 빈 칸, 잠긴 칸 구분 | 카드를 눌러 상세 또는 상점으로 이동 |
| 마리 상세 | 왼쪽 그림과 기본 정보. 오른쪽 상태와 조절 | 돌봄, 별명, 크기, 모습, 표시, 진화 |
| 도감 | 왼쪽 번호·이름 목록. 오른쪽 선택한 종의 상세 | 검색, 해금 조건, 진화 사슬, 저작자 확인 |
| 상점 | 왼쪽 상품 목록. 오른쪽 효과·대상·가격 | 대상 선택 후 구매 |
| 연결 | Claude Code, Codex CLI, Gemini CLI 카드 | 개별 연결, 해제, 상태 새로고침 |
| 설정 | 표시, 동작, 언어, 시작 항목 | 값 변경과 결과 확인 |

원작의 파티 카드, 요약 화면, 도감 목록, 프렌들리숍 목록 구조를 따른다.
화면 복제보다 선택 위치, 상태 막대, 대화 상자의 계층을 참고한다.
포켓몬 그림은 기존 PMD 자산을 사용한다. 외부 웹 글꼴이나 새 npm 패키지는 필요 없다.

### 시각 규칙

- 어두운 청록색 틀, 밝은 본문, 민트색 선택 표시를 사용한다.
- 잠긴 칸과 숨긴 마리는 색뿐 아니라 글자로도 구분한다.
- 본문은 시스템 글꼴 14~16px를 사용한다. 작은 픽셀 글꼴을 본문에 쓰지 않는다.
- 포켓몬 그림은 정수 배율로 그린다. 확대 시 보간을 끈다.
- Tab과 방향키로 탭·목록을 이동한다. Enter로 선택한다. Escape로 상세 화면을 닫는다.
- 포커스 테두리를 표시한다. 처리 중인 버튼에는 동작 상태를 표시한다.
- 창 크기와 화면 배율이 바뀌어도 탭과 주요 버튼은 남긴다.
- 작은 높이에서는 상세 본문만 스크롤한다. 파티 6칸은 카드 높이를 줄여 유지한다.
- 감소된 모션 설정에서는 그림 애니메이션과 전환 효과를 줄인다.

## 3. 진입, 종료, 복구

| 시작점 | 열리는 화면 |
|---|---|
| 포켓몬 우클릭 → `설정…` | 파티 탭의 해당 마리 상세 |
| 트레이 → `설정…` | 마지막 탭. 처음이면 파티 |
| `pokebuddy settings` | 실행 중인 육성 앱의 설정창 |
| 설정창이 이미 열림 | 기존 창을 앞으로 가져옴. 새 창은 만들지 않음 |
| 설정창 닫기 | 설정창만 닫음. 무대와 육성은 계속 실행 |

런타임마다 설정창을 하나만 둔다. 다른 프로세스의 저장에는 기존 writer/mailbox 규칙을 적용한다.
여러 VS Code 창의 파티 배분은 기존 규칙을 유지한다. 이번 단계에서 재설계하지 않는다.

`pokebuddy settings`는 새 게임이나 동반자를 자동 생성하지 않는다.
연결할 앱이 없으면 `실행 중인 동반자가 없습니다. pokebuddy companion으로 시작하세요.`를 출력한다.
VS Code 창 모드에는 확장 명령 `Pokebuddy: 설정 열기`를 추가한다.
이 명령은 해당 창의 펫으로 요청을 보낸다. 다른 창의 펫을 선택하지 않는다.
세션 펫은 기존 단축키를 유지한다. 설정창에서는 표시 설정만 사용할 수 있다.

숨김과 고스트 모드는 설정창에 영향을 주지 않는다.
동반자는 트레이와 CLI로 설정창을 다시 열 수 있다.
창 모드는 확장 명령과 기존 고스트·숨김 단축키로 복구할 수 있다.
트레이를 만들지 못하면 메뉴를 줄이기 전에 설정창을 열어 복구 경로를 남긴다.

## 4. 파티와 상세

### 파티 카드

카드 순서는 저장된 파티 순서다. 카드 재정렬은 제공하지 않는다.
무대의 앞뒤 순서는 소환 순서다. 카드 순서를 바꾸는 기능으로 혼동하지 않게 한다.

| 카드 상태 | 표시 문구 | 선택 결과 |
|---|---|---|
| 마리가 있음 | 이름, 성격, 기분, 친밀도, 배고픔 | 마리 상세 |
| 마리가 숨겨짐 | 위 정보 + `무대에서 숨김` | 마리 상세 |
| 구매한 빈 칸 | `빈 칸` / `새 포켓몬을 맞이하세요` | 상점의 새 종 목록 |
| 다음 잠긴 칸 | `잠긴 칸` / `칸 늘리기 · 240 P` | 상점의 파티 칸 상품 |
| 이후 잠긴 칸 | `잠긴 칸` / `앞 칸부터 열 수 있어요` | 같은 파티 칸 상품 |

가격은 열린 칸 수로 계산한다. 예를 들어 3칸이 열렸다면 다음 칸은 240 P다.
파티가 비어 있으면 `함께할 포켓몬을 선택하세요.`와 스타터 선택 진입을 표시한다.
reader에서는 writer의 선택 결과를 기다린다. 설정창이 임의로 스타터를 만들지 않는다.

### 마리 상세

- 왼쪽: 현재 모습, 이름, 실제 종, 성격, 함께한 날짜.
- 오른쪽: 친밀도, 기분, 배고픔, 오늘 얻은 친밀도와 하루 상한.
- 친밀도는 다음 진화 문턱을 표시한다. 진화가 없으면 다음 단계 보상을 표시한다.
- 모든 문턱을 달성한 경우 누적 친밀도와 `모든 단계 달성`을 표시한다.
- 별명은 `저장`을 눌러 확정한다. 입력 중 새 상태가 와도 입력을 덮지 않는다.
- 크기 슬라이더는 미리보기를 바꾼다. 손을 놓거나 키보드 조절이 끝나면 한 번 저장한다.
- 모습은 같은 진화 사슬에서 해금한 종만 선택한다. 실제 종과 친밀도는 바꾸지 않는다.
- 다른 색과 에버스톤은 구매한 권리만 켜고 끈다. 없으면 `상점에서 구매`를 표시한다.
- 성격 변경은 대상 마리가 선택된 민트 상품으로 이동한다.
- `화면에 보임`은 그 마리만 숨긴다. 육성 기록을 삭제하지 않는다.
- 놓아주기와 파티 삭제는 S5에서 제공하지 않는다.

돌봄 버튼은 `밥 주기`, `놀아주기`다.
먹이가 있으면 `먹이 1개 사용 · 효과 2배`를 표시한다.
대기 중에는 `8분 뒤 가능`을 표시한다. 배가 부르면 `배가 불러요`를 표시한다.

진화 후보에는 이름과 조건을 각각 표시한다.
예: `블래키 · 친밀도 500 · 밤 18:00~06:00`.
가능한 후보만 실행할 수 있다. 불가능한 이유는 버튼 옆에 남긴다.
실행 버튼은 `블래키로 진화`처럼 대상 종을 명시한다.
그림 확인 중에는 `진화 준비 중…`을 표시한다. 완료 후 같은 마리의 상세를 갱신한다.

## 5. 도감

목록은 전국도감 번호순으로 표시한다. 같은 번호의 폼은 해당 종 아래에 묶는다.
기본 목록은 해금 규칙이 있는 종과 보유한 종을 합친다.
검색은 한국어 이름, 영어 이름, 번호를 받는다. 검색어와 스크롤 위치를 유지한다.
필터는 `전체 / 해금 / 미해금`이다.

미해금 종도 번호와 이름, 조건을 확인할 수 있다. 그림만 실루엣으로 표시한다.
그림이 없으면 공통 실루엣과 `그림 준비 중`을 표시한다.
목록 전체의 PMD 그림을 한 번에 받지 않는다. 선택한 종과 현재 보이는 카드만 요청한다.

선택한 종의 상세에는 다음 내용을 표시한다.

1. 번호, 이름, 해금 여부.
2. 조건별 현재 값과 목표 값. 여러 조건은 모두 충족해야 한다고 표시.
3. 같은 사슬의 진화 관계. 밤 조건과 친밀도 문턱 포함.
4. 얻는 방법. `상점에서 얻기`, `진화로 얻기`, 또는 미충족 조건.
5. 그림 저작자와 라이선스. 정보를 못 받으면 `저작자 정보를 불러오지 못했습니다.`와 재시도.

해금 여부와 현재 진화 가능 여부는 구분한다.
과거에 해금한 밤 진화라도 낮에는 실행할 수 없다.
폼 그림을 정확히 연결하지 못한 경우 다른 폼의 그림을 대신 표시하지 않는다.

## 6. 상점

분류는 `새 포켓몬 / 파티 칸 / 도구`다.
왼쪽 목록은 상품 이름과 가격을 표시한다. 오른쪽은 효과와 구매 대상을 표시한다.
상점 진입만으로 포인트를 차감하지 않는다.

| 상품 | 선택 항목 | 구매 버튼 |
|---|---|---|
| 새 종 | 해금된 종 | `피카츄 얻기 · 0 P` 또는 실제 가격 |
| 파티 칸 | 다음 칸 자동 선택 | `4번째 칸 열기 · 240 P` |
| 민트 | 대상 마리 + 변경할 성격 | `민트 구매 · 40 P` |
| 먹이 | 공용 재고. 한 번에 1개 | `먹이 구매 · 10 P` |
| 에버스톤 | 대상 마리 | `에버스톤 구매 · 30 P` |
| 다른 색 | 대상 마리 + 현재 선택된 모습 | `다른 색 구매 · 200 P` |

가격은 `data/shop.json`과 `unlocks.json`에서 읽는다. 화면에 가격 사본을 만들지 않는다.
대상, 효과, 비용을 구매 버튼 옆에 표시한다. 별도의 반복 확인 대화 상자는 두지 않는다.

| 상태 | 표시와 행동 |
|---|---|
| 포인트 부족 | `80 P가 더 필요합니다.`. 구매 비활성 |
| 빈 칸 없음 | `빈 파티 칸이 없습니다.` + `칸 늘리기` 이동 |
| 최대 6칸 | `모든 파티 칸을 열었습니다.` |
| 이미 보유 | `이미 구매했습니다.` + 해당 마리 상세 이동 |
| 현재 성격 선택 | `현재 성격입니다.`. 민트 구매 비활성 |
| 처리 중 | 구매 버튼 비활성. `그림 확인 중…` 또는 `구매 중…` |
| 성공 | 잔액과 재고 갱신. 새 마리를 얻었다면 상세 화면 이동 버튼 |
| 그림·저장 실패 | 이유를 표시. 잔액 유지. 명시적 재시도 버튼 |
| 응답 지연 | `결과를 확인하고 있습니다.`. 먼저 최신 상태를 조회. 자동 재구매 금지 |

## 7. 연결

각 CLI를 독립된 카드로 표시한다. 카드마다 `연결` 또는 `연결 해제`를 둔다.
버튼 아래에 `선택한 CLI의 상태 훅을 등록합니다.`를 표시한다.
설치, 계정 로그인, 외부 메시지 전송은 이 버튼의 기능이 아니다.

연결 상태는 실제 훅 등록 상태를 기준으로 한다. `save.agents.connected`만 신뢰하지 않는다.
상태는 `미설치 / 연결 안 됨 / 연결됨 / 확인 필요`로 구분한다.
등록과 사용량 감지는 별도로 표시한다. 연결됐다는 이유로 토큰 읽기가 가능하다고 표시하지 않는다.

- Claude: `오늘 감지한 토큰 48,210`. 앱이 감지한 분량임을 표시.
- Codex·Gemini: `토큰 집계 미지원 · 작업 시간으로 적립`. 숫자 0으로 가장하지 않음.
- 사용량이 없는 날: `오늘 감지한 토큰 0`. 이전 날짜의 값을 오늘 값으로 표시하지 않음.
- 오류: `설정을 읽을 수 없습니다.` 또는 `훅 파일을 찾을 수 없습니다.` + 재시도.

현재 저장에는 CLI별 친밀도 증가량이 없다.
따라서 연결 카드에서 CLI별 친밀도를 추정하지 않는다.
하단에 파티 전체의 `오늘 작업으로 얻은 친밀도`만 표시한다. 숨긴 마리의 기존 적립도 포함한다.

훅 원본이 없으면 전용 결과 코드 `hook-source-missing`을 사용한다.
기존 사용자 훅은 보존한다. 변경 전 백업과 기존 setup의 등록·해제 규칙을 재사용한다.
연결 탭에 들어가는 것만으로 파일을 변경하지 않는다.

## 8. 설정과 적용 범위

| 항목 | 범위 | 저장·반영 |
|---|---|---|
| 무대 표시 | 현재 무대 | 현재 실행에만 적용. 설정창은 계속 표시 |
| 고스트 모드 | 실행 모드별 | 해당 모드 기본값 저장. 같은 모드의 열린 무대에 반영 |
| 다른 앱에서도 표시 | 세션·창 모드별 | 해당 모드 기본값 저장. 동반자에서는 항상 위임을 설명 |
| 잠들기 기준 | 모든 마리 | 기본 시간만 변경. 성격·종 배율 유지 |
| 언어 | 앱 공통 | 한국어·English. 설정창과 메뉴를 즉시 갱신 |
| 로그인 시 시작 | 동반자 | 운영체제 등록 성공 후 값 표시 |

모드별 표시 설정은 `config.json`의 새 선택 필드에 둔다.
옛 `clickThrough`, `keepVisible`은 해당 필드가 없을 때의 기본값으로 읽는다.
환경변수로 받은 이번 실행 값은 사용자가 설정창에서 직접 바꾸기 전까지 유지한다.
설정창에서 바꾼 값만 저장한다. 다른 프로세스의 최신 설정과 창 위치를 덮지 않는다.
공유 설정의 읽기·병합·쓰기는 별도 설정 잠금 안에서 실행한다. 원자적 파일 교체만으로 경합을 해결했다고 판단하지 않는다.
잠금 획득에 실패하면 저장하지 않고 이유를 반환한다. 잠금 소유자 종료 후 회수 규칙도 검사한다.

잠들지 않음은 수면 진입만 막는다. 산책, 돌봄, 작업 반응은 계속 동작한다.
수면 기준을 바꿔도 집, 소환 순서, 진행 중인 드래그를 초기화하지 않는다.
실행 중인 마리의 현재 비활동 시간과 새 기준으로 다음 틱부터 판단한다.

자동 시작은 운영체제 상태를 읽어 표시한다. 저장 파일의 희망값만 보여 주지 않는다.
개발 실행에서는 `앱 설치 후 사용 가능`을 표시한다.
배포 앱은 `--companion`으로 시작하고 단일 실행 검사를 수행한다.
경로·인자 처리와 macOS 앱 식별은 S6 패키징 계약으로 이어진다.

## 9. 상태와 명령 계약

설정창은 저장 파일을 직접 읽거나 쓰지 않는다.
표시용 자료는 메인이 만들고, 변경은 기존 dispatcher를 통과한다.
코드는 이번 단계에서 추가하지 않는다. 아래는 구현할 계약이다.

### 읽기

`settings:snapshot`은 다음 자료를 반환한다.

- 상태 번호, 관측 시각, 실행 모드, 사용 가능한 기능.
- 저장 v2의 파티, 칸, 포인트, 재고, 해금, 오늘 통계.
- 파티별 돌봄 가능 여부, 진화 후보와 이유, 모습 선택지.
- 도감 번호·이름·조건, 상점의 현재 가격.
- 실제 에이전트 연결 상태와 지원하는 적립 방식.
- 현재 적용된 설정, 자동 시작 지원 여부와 운영체제 상태.

그림은 별도 `settings:art` 요청으로 받는다. 종/모습 키만 허용한다.
메인이 기존 로더와 저작자 자료를 사용한다. 임의 URL이나 파일 경로는 받지 않는다.

설정창이 보일 때 상태를 최대 초당 한 번 갱신한다. 작업 성공 직후에는 즉시 갱신한다.
쓰기 권한이 없는 런타임은 writer에서 최신 상태를 조회한다. 오래된 로컬 저장만으로 완료를 판단하지 않는다.
창이 닫히거나 숨으면 구독과 타이머를 중단한다. 그림 애니메이션은 별도 렌더러 시계로 진행한다.
새 상태를 받아도 입력 중인 별명, 선택한 탭, 검색어, 스크롤, 포커스를 유지한다.

### 쓰기

| 화면 동작 | 기존 명령 또는 추가 계약 |
|---|---|
| 밥·놀기 | `feed`, `play` |
| 마리 표시 | `party.show`, `party.hide` |
| 별명·크기 | `pet.set`에 `nick`, `size` 검증 추가 |
| 모습·색 | `pet.look` |
| 에버스톤 장착 | 기존 `pet.set`의 `everstone` |
| 구매·진화 | `shop.buy`, `evolve` |
| 연결·해제 | `agent.connect`, `agent.disconnect` 처리기 추가 |
| 설정 변경 | `settings.set`의 허용 키, 값, 범위 확장 |
| 설정창 열기 | `settings.open` 추가. 저장 변경 없이 창만 조작 |

설정창의 요청에는 요청 ID를 붙인다. 같은 요청의 중복 처리는 막는다.
화면은 한 번의 구매를 두 번 전송하지 않는다.
writer 교체와 응답 유실을 포함한 영속 중복 방지는 구현 전에 mailbox 규약과 함께 확정한다.
응답이 불확실하면 자동으로 재시도하지 않고 결과 조회를 먼저 한다.
권한, 대상, 잔액, 그림, 진화 조건은 메인이 마지막으로 검사한다.

### 저장과 실패

포켓몬 변경은 저장 v2에 반영한다. 스키마 버전을 올리지 않는다.
환경 설정 저장은 성공 여부를 반환하도록 바꾼다. 현재 `saveConfig`의 실패 무시 동작은 UI에 사용할 수 없다.
파일 저장에 실패하면 메모리 값과 화면 선택을 이전 값으로 되돌린다.
운영체제 자동 시작 변경과 파일 저장은 별도 결과로 다룬다. 실패 시 실제 운영체제 상태를 다시 조회한다.
이미 등록된 훅은 저장 통계 갱신 실패만으로 되돌리지 않는다. 실제 등록 상태와 오류를 함께 표시한다.

## 10. 창과 IPC

- 투명 무대와 설정창은 별도 BrowserWindow로 만든다.
- 설정창은 일반 포커스 창이다. 무대 클릭 통과와 항상 위 설정을 물려받지 않는다.
- contextIsolation과 sandbox를 켠다. 렌더러의 Node 접근을 막는다.
- 설정창 전용 preload에는 허용된 읽기·명령·그림 요청만 노출한다.
- IPC마다 sender와 최상위 frame이 설정창인지 검사한다.
- 요청의 키, 문자열 길이, 숫자 범위, 명령을 검사한다. `from`은 메인이 `settings`로 지정한다.
- 원격 문서 이동과 새 창 생성을 막는다. 출처 링크만 허용 목록으로 외부 브라우저에 연다.
- 창을 닫으면 handler와 listener를 해제한다. 다시 열어도 중복 호출이 없어야 한다.
- 설정창을 닫는 동작과 앱 종료 동작을 구분한다.

## 11. 구현할 파일 경계와 순서

| 순서 | 작업 | 종료 기준 |
|---|---|---|
| 1 | `src/shared/settings.d.ts` 표시·명령·기능 계약 | 메인과 렌더러가 같은 타입 사용 |
| 2 | 별명·크기·연결·설정 처리기, 설정 저장 성공 반환 | 입력 검증과 실패 복원 검사 통과 |
| 3 | 설정창 생성, 전용 preload, 읽기 자료 구성 | 열기·닫기·재열기·IPC 출처 검사 통과 |
| 4 | 파티, 상세, 도감, 상점 화면 | 기존 S4 기능을 화면에서 완료 가능 |
| 5 | 연결, 설정, 언어 전환 | 결과와 실제 상태 일치 |
| 6 | CLI·확장 진입, 메뉴 축소 | 숨김·고스트 상태에서 복구 가능 |
| 7 | 남은 JS를 TS로 이식 | 옛 코드 제거 후 CLI·설치·그림·빌드 회귀 통과 |
| 8 | 화면 검수, 실패·경합 검수, 피드백 수정 | 아래 인수 기준 충족 |

TS 이식 대상은 config, CLI, i18n, names, dex, zip, Electron 경로, PMD 로더, 빌드 스크립트다.
먼저 공통 모듈을 옮기고, 그다음 소비자를 옮긴다. 마지막에 옛 파일을 제거한다.
경로는 소스 위치가 아닌 배포 구조를 기준으로 검사한다.
`postinstall.js`는 빌드 전에 실행되므로 JS로 유지한다.
UI 변경과 TS 이식은 검수 단위를 분리한다. 이식 중 게임 규칙을 바꾸지 않는다.

## 12. 구현 후 인수 기준

- 마리 0·1·6개, 빈 칸, 잠긴 칸, 숨긴 마리의 화면이 맞다.
- 파티·도감·상점 이동 후 대상 마리와 선택 상품이 유지된다.
- 별명과 검색어가 HTML로 실행되지 않는다. 최대 길이와 한글 입력을 검사한다.
- 진화 없는 종과 분기 진화의 친밀도 표시가 맞다.
- 구매·진화 중 더블클릭, 창 닫기, 응답 지연, writer 교체를 검사한다.
- 저장 실패와 그림 실패 후 잔액, 크기, 별명, 표시 상태가 맞다.
- 읽기 전용 앱에서 보낸 명령이 writer에 도달하고 결과 화면이 갱신된다.
- 연결 버튼은 선택한 CLI만 바꾼다. 기존 훅과 사용자 설정은 보존한다.
- 지원하지 않는 토큰을 0으로 표시하지 않는다. 날짜가 바뀌면 오늘 값을 갱신한다.
- 한국어와 영어에서 글자가 잘리지 않는다. 포커스와 선택 위치를 유지한다.
- 키보드만으로 모든 필수 조작을 완료할 수 있다.
- 100%·125%·150% 화면 배율과 800×620 창을 검사한다.
- 설정창 열기·닫기를 반복해도 IPC 호출, 타이머, 메모리가 누적되지 않는다.
- 세 모드의 기동·종료, CLI 도움말, 훅 dry-run, 패키지 경로를 회귀 검사한다.
- 시험은 임시 HOME을 사용한다. 실제 훅 등록이나 자동 시작을 시험 중 변경하지 않는다.

## 13. 설계 검토와 반영

| 확인한 문제 | 설계에 반영한 내용 |
|---|---|
| 기존 예시가 열린 칸 수와 다음 칸 가격을 혼동 | 3칸이면 다음 가격 240 P로 통일 |
| 메뉴를 줄이면 숨김·고스트에서 진입이 막힐 수 있음 | 트레이, CLI, 확장 명령, 기존 단축키 유지 |
| 도감의 해금과 현재 진화 가능 여부가 다름 | 해금 표시와 진화 조건을 별도로 표시 |
| CLI별 친밀도 통계가 현재 저장에 없음 | 없는 통계를 추정하지 않고 전체 작업 적립만 표시 |
| 현재 설정 저장은 실패를 숨김 | 성공 반환과 실패 복원 계약 추가 |
| 수면 설정이 성격 배율을 지울 수 있음 | 중립 기준에 기존 배율을 곱하도록 명시 |
| 여러 프로세스가 config를 덮어쓸 수 있음 | 설정 잠금 안에서 변경 키를 병합하고 원자적으로 저장 |
| 응답이 늦을 때 구매를 재전송할 수 있음 | 대기 상태, 결과 조회, 중복 요청 계약 명시 |
| 개발 Electron을 자동 시작 앱으로 등록할 수 있음 | 배포 앱에서만 활성화하도록 제안 |
| 전체 도감의 그림을 한꺼번에 받을 수 있음 | 선택한 종과 보이는 카드만 로드 |

미확정 제안은 1절에 모았다. 구현 시 변경하면 이 문서와 시안을 함께 갱신한다.

## 14. 시안 검수 결과

2026-09-18. 별도 임시 사용자 폴더를 사용하는 숨긴 Electron 창에서 확인했다.

- 다섯 탭과 파티 상세 화면을 열었다. 가로 넘침과 누락된 그림이 없었다.
- 여섯 마리 예시에서 카드 여섯 개가 표시됐다.
- 저장 실패 예시에서 변경 취소 안내가 표시됐다.
- 1200×1040과 800×800 검수 창에서 화면을 캡처했다. 파티 여섯 칸과 하단 안내를 확인했다.
- 좁은 화면에서 블래키 그림이 잘렸다. 그림을 중앙에 배치하고 배율을 조정한 뒤 다시 확인했다.
- 상세 화면은 본문을 스크롤한다. 탭과 하단 안내는 유지한다.

이 결과는 독립 HTML 시안에만 적용한다. 구매, 저장, 연결, IPC, 실제 게임 동작은 구현하거나 검사하지 않았다. 최소 앱 창 800×620과 운영체제 화면 배율 검사는 구현 단계에 남아 있다. 시안은 예시 자료를 사용하며 모든 설계 동작을 재현하지 않는다.
