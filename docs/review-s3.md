# b5b9090 검토와 S3 구현 기록

기준: `b5b90906bb43c039b4a9fe4359df4ec3b5dc6c8c`. 2026-09-17 Windows에서 검토. 작업 전 추적 파일 변경 없음. 사용자가 제공한 `pokebuddy 동반자 설계.html`의 실제 본문은 `pokebuddy 동반자 설계_files/_t.html`에 있으며, 설계 v2와 핵심 결정이 같다. HTML의 “S2 미커밋” 표기는 이전 시점 기록이다. 원본 캡처는 보존하며 이번 변경의 결정 원본은 `design.md`와 이 문서다.

## 기존 구현 검토

저장·writer/reader 전환·mailbox·명령 처리·에이전트 사용량·무대 갱신·움직임·렌더러 계약을 확인했다. 기존 자체 확인 6벌은 통과했지만 아래 경계 사례를 놓치고 있었다.

| 중요도 | 문제와 영향 | 수정·회귀 검사 |
|---|---|---|
| 높음 | 같은 프로세스가 같은 밀리초에 같은 명령을 보내면 요청·회신 경로가 겹쳐 한 요청이 유실됨 | 요청 이름에 순번 추가. 고정 시계로 두 feed 요청을 동시에 보내 서로 다른 대상의 회신 확인 |
| 높음 | usage 파일을 잠깐 못 읽으면 seen에서 사라져 복구 시 이전 사용량을 다시 셈 | 빠진 세션의 기준점 유지. 공백→동일 누적량→새 증분 순서 검증. 음수·무한대 토큰도 제외 |
| 높음 | writer 여부를 메모리 플래그만으로 판단해 잠금 소유권을 잃어도 저장할 수 있음 | isWriter·persist에서 실제 lock 확인. 다른 살아 있는 PID로 교체 후 저장 원본 유지 검증 |
| 보통 | 같은 id의 look을 바꿔도 이전 그림·몸 크기·움직임을 계속 사용 | 새 그림과 시트를 로드하고 들기 상태 해제. 실제 createStage에 가짜 창·그림 로더를 넣어 교체 검증 |

이 결과는 확인한 경로에 대한 검토이며 모든 플랫폼 동작의 무결성을 보장하지 않는다. 기존 save.lock의 오래된 잠금 회수는 여러 프로세스가 정확히 동시에 실행되는 스트레스 검증이 남아 있다.

## S3 구현

- 성격 축 → 걷는 속도·쉬는 시간·제자리 동작·수면·만지기 반응. 사교성으로 다른 마리에게 접근/회피, 대담함으로 커서 접근/회피. 변덕은 마리별 90초 주기 중 10초 동안 한 축 변화. 수면은 기존 motion 시계가 소유하고 종의 sleepiness를 반영한다.
- 마리별 배고픔·기분·친밀도, 마리별 하루 상한, 날짜 전환, 연속 교감과 하루 첫 교감 포인트. 시작 기분은 종의 moodBase. 친밀도 감소 없음.
- 켜 두기와 작업량은 화면에 나온 마리에게만, 배고픔·기분 변화는 숨긴 마리도 적용. 꺼 둔 시간은 적립하지 않으며 절전 등 긴 틱은 5초까지만 인정.
- 토큰은 훅 누적량의 증분. 해당 작업 기록에 usage가 있으면 작업 시간 대체 적립을 하지 않음. Codex·Gemini의 별도 토큰 리더는 여전히 미구현이며 시간 대체 사용.
- feed/play/poke를 dispatcher·mailbox에 연결. writer만 상태를 쓰며 15초 주기, 돌봄 직후, 정상 종료·역할 양도 때 저장. 돌봄 저장 실패 시 메모리 효과를 되돌리고 save-failed 반환.
- 우클릭 첫 줄은 배고픔 → 낮은 기분 → 다음 진화까지 → 기분 순서 중 하나. 밥·놀기와 재사용 대기 이유 표시. 열매로 이동해 먹기, 12초 커서 따라 놀기. 필요한 동작 그림이 없으면 보유한 Nod/Idle 등으로 대체.
- CLI status에 배고픔·기분 표시. 세션 샌드박스는 게임 저장·적립 없음. 성격 목록의 저장 모듈 사본 제거.

## 초기값

주요 값은 사용자 승인(2026-09-17). 종·성격에 따른 배율은 별도로 곱한다.

| 항목 | 값 |
|---|---|
| 켜 두기 | 시간당 친밀도 +6 |
| 토큰 | 1천 토큰당 친밀도 +1, 1만 토큰당 포인트 +1 |
| 토큰을 읽지 못하는 작업 | running 시간당 친밀도 +12 |
| 하루 상한 | 마리마다 친밀도 200, 토큰 포인트는 저장 전체 50 |
| 배고픔 | 시간당 +10, 밥 −40 |
| 밥 / 놀기 | 친밀도 +8 / +6, 기분 +10 / +12, 각각 10분 대기 |
| 찌르기 / 턴 완료 | 친밀도 +1·기분 +2, 찌르기 보상 하루 10회 |
| 첫 교감 | 연속일 ×2 포인트, 최대 7일분. 토큰 포인트 상한과 별도 |
| 기분 감소 | 배고픔 70 이상: 시간당 −6, 1시간 돌봄 없음: 시간당 −3 |
| 활동성이 높은 / 낮은 마리 | 걷기 1.2 / 0.8배, 쉬는 시간 0.8 / 1.2배 |

`src/state/rules.ts`, `src/motion/params.ts`, `src/dex/natures.ts`에 규칙을 모았다. 밥·놀기 대기와 기분 세부값은 구현 초기값이며 사용 후 조정 대상이다. 캐시 읽기 토큰은 기존 0.1 가중치를 유지한다.

## 확인과 남은 실기

- 타입 검사·빌드·자체 확인 7벌. 상태 테스트는 시간 적립, 토큰 공백, 재시작, 상한, 숨김, 실패·턴 중복, 돌봄, 날짜·스트릭, 저장 왕복, 성격별 접근/회피를 확인한다.
- 무대 테스트는 그림 교체, 먹이 이동·제거, 커서 따라가기, 잠금 상실, mailbox 돌봄 왕복, 저장 실패 롤백을 포함한다. Windows에서는 기존 mac용 가짜 anchor 실행 테스트를 건너뛴다.
- 숨긴 Electron 창에서 로컬 mock 시트 3종 로드·캔버스 픽셀·화면 캡처 확인. `dist/tools/smoke-renderer.js` 사용. 임시 사용자 폴더만 사용하며 실제 게임 저장을 만들거나 수정하지 않음.
- **미확인:** 실제 PMD 그림을 쓰는 Windows 드래그·우클릭·클릭 통과, 125%/150% DPI, 6마리 CPU/GPU, macOS 회귀 실기. mock 렌더링 검사는 이를 대신하지 않는다.
- 토큰 기준점은 일시적인 읽기 실패와 삭제를 구분할 수 없어 보존한다. 장기 사용 시 오래된 세션의 기준점 정리 정책을 추가할 수 있다.

다음 단계는 S2/S3 실기 결과 반영 후 S4(해금·상점·진화). S5의 설정창과 메뉴 최소화는 아직 구현하지 않았다.
